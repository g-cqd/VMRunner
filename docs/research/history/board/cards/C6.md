# C6 — X7, part 2: see events taken inside a view's tracking loop

Model: haiku · Effort: low · Worktree: yes, `WT = ~/Developer/g-cqd/VMRunner-chains/c-app` (branch `chain/c-app`) · Chain: C, card 6 of 6 (after C5; last)

Cause, from the code: the monitor is an `NSEvent.addLocalMonitorForEvents` (lines 80-83). AppKit documents that local monitors see only events dispatched through `sendEvent`. The machine view's own drag loop dequeues events with `nextEvent(matching:...)` directly, so the 550 key presses during a drag were never counted. The fix observes every event as it leaves the queue, in an `NSApplication` subclass named by `NSPrincipalClass`, and removes the local monitor so nothing is counted twice.

     ```swift
     import AppKit

     /// The app's `NSApplication` (`NSPrincipalClass` in `Resources/Info.plist`). It only shows the input latency monitor every
     /// event the app takes from its queue, including those a view's own tracking loop takes (a drag in the machine's view),
     /// which never reach `sendEvent` or a local event monitor.
     @objc(VMRunnerApplication)
     final class VMRunnerApplication: NSApplication {
         override func nextEvent(
             matching mask: NSEvent.EventTypeMask, until expiration: Date?, inMode mode: RunLoop.Mode, dequeue deqFlag: Bool
         ) -> NSEvent? {
             let event = super.nextEvent(matching: mask, until: expiration, inMode: mode, dequeue: deqFlag)
             if deqFlag, let event { InputLatencyMonitor.current?.dequeued(event) }
             return event
         }
     }
     ```
