# C4 — X6, part 4: the machine view takes the keyboard when the display appears

Model: haiku · Effort: low · Worktree: yes, `WT = ~/Developer/g-cqd/VMRunner-chains/c-app` (branch `chain/c-app`) · Chain: C, card 4 of 6 (after C3; next C5)

Decision: the view takes the keyboard on its first arrival in a window. That happens at start, and when a running machine is selected, which is when the user expects to type into it. It never takes it again, so the sidebar's keyboard navigation is not interrupted by re-layout.

     ```swift
     /// The machine's view takes the keyboard the first time the display is in a window, so typing reaches the guest without a
     /// click first. Only once: a later move must not take the keyboard from wherever the user put it.
     override func viewDidMoveToWindow() {
         super.viewDidMoveToWindow()
         // AppKit declares `window` unowned(unsafe); it is alive for the duration of this callback and not kept.
         guard !gaveKeyboard, let window = unsafe self.window else { return }
         gaveKeyboard = window.makeFirstResponder(machineView)
     }
     ```
