Why: the app will run a container as a machine next to the virtual machines, and the controller, the toolbar, the menu and the detail pane all assume a `VZVirtualMachine` today. This card puts a neutral seam under them and changes no behaviour of a virtual machine; nothing runs a container yet. Decisions:
- `Workload` holds what the controller drives whatever the machine runs (start, stop, request a stop, the two stop reports, the kill switch) plus `capabilities`, an `OptionSet` of `display` (a framebuffer), `pause`, `suspend` and `networkActivity`. `GuestMachine` now refines `Workload` and keeps only `virtualMachine`. The four calls that only some workloads support (`restoreState`, `saveState`, `pause`, `resume`) are `Workload` requirements with default implementations that throw `WorkloadUnsupportedError`, so the controller needs no casts and a workload without the capability cannot be driven into them silently.
- The controller reads `capabilities` in three places: `canPause` (new; the toolbar and the Machine menu use it in place of `state.canPause`), the suspend support it adopts (a workload without `suspend` is adopted as "unavailable" with a reason, so `canSuspend`, `suspend()` and the refusal text all follow), and `MachineModel` (`networkActivity`, `phase`). `VMController.capabilities` is empty until a machine exists. The toolbar still draws the same buttons, disabled rather than hidden: hiding them while a machine is being prepared would make a virtual machine's toolbar flicker.
- `RoutingMachineFactory` is the controller's default factory: `config.workload == .vm` goes to `VZMachineFactory`, `.container` to the injected container factory, which defaults to `UnavailableContainerFactory` (every start throws "Containers are not available in this build."). A test's `FakeFactory` is still injected exactly as before. The card that adds the container engine passes its own factory as `containers`.
- `MachineModel.Phase.running` carries a `RunningDisplay`: `.virtualMachine(VZVirtualMachine, DisplaySettings)` as before, or `.workloadLog` for a running machine that has no `display` capability. `MachineView` switches over both; `.workloadLog` shows a placeholder until the card that adds the log view.
- The two start guards of the library (`startMachine`, `startAndWait`, with `containerStartRefusal`) STAY. The controller's start is written for a virtual machine (it picks a display size, writes it to the stored configuration, renews a MAC address, prepares a disposable copy of the disk); a container machine must bypass that, which is the engine card's decision, so routing alone does not make the guards redundant. That card replaces them.

import Foundation

/// What a running workload can do, so the controller and the interface offer a control only when the workload has it.
struct WorkloadCapabilities: OptionSet, Sendable {
    let rawValue: Int

    /// A framebuffer to show; without it the workload shows a log.
    static let display = Self(rawValue: 1 << 0)
    /// Pause and resume.
    static let pause = Self(rawValue: 1 << 1)
    /// Save the state to disk and restore it at the next start.
    static let suspend = Self(rawValue: 1 << 2)
    /// A filtered network stack whose flows the interface lists.
    static let networkActivity = Self(rawValue: 1 << 3)

    /// Everything a virtual machine does.
    static let virtualMachine: Self = [.display, .pause, .suspend, .networkActivity]
}

/// Why a workload refuses a call its capabilities do not include.
struct WorkloadUnsupportedError: LocalizedError, Equatable {
    let operation: String
    var errorDescription: String? { "This machine does not support \(operation)." }
}

/// What the controller drives, whatever the machine runs: a virtual machine (`GuestMachine`) or a container. A test supplies
/// its own to run the controller's transitions without starting anything.
@MainActor
protocol Workload: AnyObject {
    /// What this workload can do. The controller and the interface read it; a call outside it throws.
    var capabilities: WorkloadCapabilities { get }
    /// Whether a stop is allowed now. A virtual machine does not allow one while a start, a pause or a resume is in flight.
    var canStop: Bool { get }
    /// Called when the guest powers off by itself, and when the machine stops because of an error. The controller sets them
    /// once, right after it receives the machine, and clears them when it lets the machine go. The controller's own state
    /// never copies the workload's: it follows the outcome of each call and these two reports.
    var onGuestStopped: (@MainActor () -> Void)? { get set }
    var onStoppedWithError: (@MainActor (_ message: String) -> Void)? { get set }
    /// The kill switch of this run, when the workload has one, for the toolbar.
    var networkCutoff: NetworkCutoff? { get }

    func start() async throws
    /// Presses the guest's power button.
    func requestStop() throws
    /// Pulls the plug.
    func stop() async throws

    /// The next four are for the `suspend` and `pause` capabilities; a workload without them keeps the defaults, which throw.
    func restoreState(from url: URL) async throws
    func saveState(to url: URL) async throws
    func pause() async throws
    func resume() async throws
}

extension Workload {
    func restoreState(from url: URL) async throws { throw WorkloadUnsupportedError(operation: "restoring saved state") }
    func saveState(to url: URL) async throws { throw WorkloadUnsupportedError(operation: "suspending") }
    func pause() async throws { throw WorkloadUnsupportedError(operation: "pausing") }
    func resume() async throws { throw WorkloadUnsupportedError(operation: "resuming") }
}

import Foundation

/// Sends each start to the factory of what the machine runs: a virtual machine to the framework's factory, a container to
/// the container factory.
struct RoutingMachineFactory: MachineFactory {
    let virtualMachines: any MachineFactory
    let containers: any MachineFactory

    init(
        virtualMachines: any MachineFactory = VZMachineFactory(), containers: any MachineFactory = UnavailableContainerFactory()
    ) {
        self.virtualMachines = virtualMachines
        self.containers = containers
    }

    func prepare(
        _ config: VMConfig, bundle: VMBundle, display: (width: Int, height: Int), suspendAllowed: Bool
    ) async throws -> PreparedMachine {
        switch config.workload {
        case .vm:
            try await virtualMachines.prepare(config, bundle: bundle, display: display, suspendAllowed: suspendAllowed)
        case .container:
            try await containers.prepare(config, bundle: bundle, display: display, suspendAllowed: suspendAllowed)
        }
    }
}

/// The container factory of a build that has no way to run a container: every start fails with a message that says so.
struct UnavailableContainerFactory: MachineFactory {
    struct Unavailable: LocalizedError, Equatable {
        var errorDescription: String? { "Containers are not available in this build." }
    }

    func prepare(
        _ config: VMConfig, bundle: VMBundle, display: (width: Int, height: Int), suspendAllowed: Bool
    ) async throws -> PreparedMachine {
        throw Unavailable()
    }
}
