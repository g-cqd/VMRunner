**Risky:** none in the code (nothing here starts the runner). Two things to know when you run it. The one real build of the
bundle (Commands, step 5) builds the container package for the first time in a scratch directory, which takes minutes and
several GiB; if a step reports `No space left on device`, free space and rerun that step, it is not a failure of the card.
And the order inside `AppBundler.run()` is the point of the card (the runner is signed before the app is, so the app's
signature seals it): do not reorder it.

Why: the app is to start a container as a machine of its own (chain S), and for that the signed runner has to travel inside
the app: `VMRunner.app/Contents/Helpers/ContainerRunner`, ad hoc signed with the hardened runtime and
`Resources/ContainerRunner.entitlements`, signed before the app bundle itself (a nested executable is signed first, and the
app's signature then seals it; `codesign --verify --deep --strict` on the app passes only then). This card makes
`vmr build-app` do that, and nothing else.
- **Build.** The runner is built with `ContainerSigner`'s existing path (so `BuildTools.build`, which already passes
  `--only-use-versions-from-resolved-file`, the pinned versions of `Packages/Containers/Package.resolved`, no resolution
  beyond them), in the scratch directory `NestedPackage` gives it (`.build-packages/Packages-Containers`, shared with
  `vmr check build`), and in the app's configuration (`debug` for `debug`, `release` for `release`). It is acquired first,
  right after the cheap file checks, because it is the long build; a failed runner build ends the run before the app is
  compiled. The built executable is copied (never moved) into the bundle and the copy is signed; the build product is not
  touched.
- **Policy.** `EntitlementPolicy.runnerAllowed` is the runner's whole policy: `com.apple.security.virtualization` = true and nothing
  else. The runner's file is judged against it before anything is built (an extra key, even one the app may carry such as
  audio input, or a wrong value, is refused with the file's name; a file that lacks virtualization is refused by the
  existing "must grant" check) and the signature is read back to equal the file, as before. Before this card
  `ContainerSigner` judged the runner's file against the app's list, which let audio input through.
- **Hardened and arm64e.** `--hardened` and `--arm64e` change only the app: the runner is signed with the same file in every
  profile (the hardened-process family is the app's; whether the runner could take it is untested), and it is built for the
  host architecture.
- **Escape hatch.** `--container-runner PATH` embeds an executable that is built already, copied and signed here, instead of
  building the package: the pattern `vmr container-sign --binary` already has. It is also what lets the tests exercise the
  bundle without building the nested package. The default always embeds a freshly built runner.
- **Output.** The signer's two result lines for the embedded runner are printed with a `runner: ` prefix, so the app's own
  `entitlements OK (...)` line stays the only line of that form. The existing test that looked for that text anywhere in the
  output now looks for the whole line.
