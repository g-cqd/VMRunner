Why: the owner and an authorised agent need one command that builds the runner, signs it and runs an image and a command in a
real virtual machine, with the runner's options and a scratch directory, without typing the pieces by hand. This card adds
`vmr container-run` beside `vmr container-sign`; it reuses `ContainerSigner` (so `--binary PATH` skips the build, as there),
makes the scratch directory, starts the signed runner with the options in the runner's own order, passes its standard output
and error through, and exits with its status.
- **Gate.** The convention of the repository for a command that boots a virtual machine is an explicit opt-in flag, `vmr sandbox run --boot`
  (`vmr guest start` has only the words of its abstract). So `container-run` refuses, with status 64 and before it builds anything,
  unless `--boot` is given; the refusal quotes CONTRIBUTING.md ("Real-guest runs") and tells to pass `--boot` to confirm
  that the run is authorised. The rule the discussion quotes is the first sentence of that section: "Run it only when the
  owner has authorised real-guest runs for the session". The same section's caps are enforced where the tool can: at most
  2 processors and 2048 MiB (`--memory` from 128), and a hard run-time limit `--max-seconds` (900 by default, 3600 at most; status 124 when it
  stops the runner).
- **Scratch.** `--scratch DIR` reuses a directory (checked with `GuestScratch`: never the root, the home folder or the Library; created 0700, or
  an existing one must be private), so the kernel and image store survive between runs. Without it the directory is new
  (`<temporary directory>/vmr-container-run-<UUID>`, 0700) and its path is printed on standard error with a reminder to delete it;
  the command never deletes a directory.
- **Output.** The runner writes to the same descriptors. The command's own lines (the signer's two result lines, the scratch path) go to standard
  error, so `--json` leaves standard output to the runner's events; `swift build`'s progress still goes to standard output, so use `--binary` for a clean stream.
  With `--json` the runner reads standard input (a `stop` line or its end stops the container, status 75), so the command lets it inherit this
  process's standard input; without `--json` the runner gets an empty one.
- **Signals.** SIGINT and SIGTERM stop the runner (SIGTERM, then SIGKILL after five seconds) before the command exits with 128 plus the signal's
  number, so the runner is never left running; the subprocess library closes its descriptors.
- **Pure plan.** The checking of the options and the runner's command line are in `ContainerRunPlan`, which imports nothing from the nested package; an
  option left out is left out of the command line, so the runner's own defaults apply, and the runner still checks its own options (image,
  command, environment) and refuses a bad one before anything starts.

import Foundation

/// What `vmr container-run` was asked to do, checked, and the command line it gives the runner. Pure: it reads no file and
/// starts nothing, so a test covers it without the runner or its package.
///
/// The limits are those of CONTRIBUTING.md's real-guest runs (at most 2 CPUs and 2048 MiB, a hard run-time limit), because
/// running the runner boots a virtual machine. The runner checks the rest of its options itself and refuses what it does not
/// accept before anything starts.
struct ContainerRunPlan: Equatable {
    static let maximumCPUs = 2
    static let maximumMemoryMiB = 2_048
    static let defaultMaximumSeconds = 900
    static let maximumSecondsLimit = 3_600
    /// The runner's own lowest memory size, so that a request below it is refused here, before a build.
    static let minimumMemoryMiB = 128

    /// How the container is attached to a network, as the runner names it.
    enum Network: String, CaseIterable, Equatable {
        case none
        case loopback
    }

    /// The options as typed.
    struct Options: Equatable {
        /// `--boot`: the caller confirms that this boots a real virtual machine.
        var confirmed = false
        /// `--scratch`; nil makes a fresh directory.
        var scratch: String?
        var image: String?
        var command: [String] = []
        var cpus: Int?
        var memoryMiB: Int?
        var environment: [String] = []
        var network: Network?
        var json = false
        var maximumSeconds = ContainerRunPlan.defaultMaximumSeconds
    }

    /// The places a plan depends on, injected so that a test fixes them.
    struct Surroundings {
        var workingDirectory: URL
        var temporaryDirectory: URL
        /// Makes the default scratch directory's name unique.
        var token: String
        var home: URL

        static func current() -> Self {
            Self(
                workingDirectory: URL(fileURLWithPath: FileManager.default.currentDirectoryPath, isDirectory: true),
                temporaryDirectory: FileManager.default.temporaryDirectory,
                token: UUID().uuidString.lowercased(),
                home: FileManager.default.homeDirectoryForCurrentUser)
        }
    }

    let options: Options
    /// The absolute scratch directory the runner is given.
    let scratch: URL
    /// Whether ``scratch`` is a fresh directory of this run's own, not one the caller named.
    let isFresh: Bool

    /// Checks `options`.
    ///
    /// - Throws: ``ToolError`` with the usage status, naming the option that is wrong. Without `--boot` nothing else is
    ///   looked at: the run is refused.
    static func make(_ options: Options, in surroundings: Surroundings = .current()) throws -> Self {
        guard options.confirmed else {
            throw ToolError.usage(
                """
                container-run boots a real virtual machine. Only the repository owner, or an agent the owner has authorised \
                for the session, runs real guests (CONTRIBUTING.md, "Real-guest runs"). Pass --boot to confirm that this run is \
                authorised.
                """)
        }
        if let cpus = options.cpus, !(1...maximumCPUs).contains(cpus) {
            throw ToolError.usage("--cpus must be from 1 to \(maximumCPUs), the cap of a real-guest run, not \(cpus)")
        }
        if let memory = options.memoryMiB, !(minimumMemoryMiB...maximumMemoryMiB).contains(memory) {
            throw ToolError.usage(
                "--memory must be from \(minimumMemoryMiB) to \(maximumMemoryMiB) MiB, the cap of a real-guest run, not \(memory)")
        }
        guard (1...maximumSecondsLimit).contains(options.maximumSeconds) else {
            throw ToolError.usage("--max-seconds must be from 1 to \(maximumSecondsLimit)")
        }
        if let requested = options.scratch {
            let scratch = try GuestScratch(path: requested, workingDirectory: surroundings.workingDirectory, home: surroundings.home)
            return Self(options: options, scratch: scratch.root, isFresh: false)
        }
        let fresh = surroundings.temporaryDirectory.appending(path: "vmr-container-run-\(surroundings.token)", directoryHint: .isDirectory)
        return Self(options: options, scratch: fresh.standardizedFileURL, isFresh: true)
    }

    /// The runner's arguments, in the order its usage lists them; an option that was not given is left out, so the runner's
    /// own default applies.
    var runnerArguments: [String] {
        var arguments = [scratch.path]
        if let image = options.image { arguments += ["--image", image] }
        for argument in options.command { arguments += ["--command", argument] }
        if let cpus = options.cpus { arguments += ["--cpus", "\(cpus)"] }
        if let memory = options.memoryMiB { arguments += ["--memory", "\(memory)"] }
        for entry in options.environment { arguments += ["--env", entry] }
        if let network = options.network { arguments += ["--network", network.rawValue] }
        if options.json { arguments.append("--json") }
        return arguments
    }
}

```swift
import Foundation

/// `vmr container-run`: signs the runner (``ContainerSigner``), makes its scratch directory, runs it with the plan's options and
/// returns its exit status. Running it boots a virtual machine.
///
/// The runner writes to this process's standard output and error directly. SIGINT and SIGTERM end it: the runner is stopped
/// (SIGTERM, then SIGKILL after five seconds) before this process exits, so it is never left running, and the status is
/// 128 plus the signal's number.
struct ContainerRun {
    /// The status when the run-time limit stopped the runner, as for `vmr guest exec`.
    static let timedOutStatus: Int32 = 124

    let root: URL
    /// A runner that is built already, signed here instead of building one.
    let binary: URL?
    let configuration: AppBundler.Configuration
    let plan: ContainerRunPlan

    private enum Outcome: Sendable {
        case finished(CommandResult)
        case signalled(Int32)
    }

    func run() async throws -> Int32 {
        let runner = try await ContainerSigner(
            root: root, binary: binary, configuration: configuration, report: { Output.err($0) }
        ).run()
        try GuestScratch.ensurePrivate(plan.scratch)
        Output.err("scratch: \(plan.scratch.path)\(plan.isFresh ? " (new; delete it when you are done)" : "")")

        var spec = CommandSpec(executable: runner.path, arguments: plan.runnerArguments)
        // The runner reads standard input only with --json, where the end of input stops the container.
        spec.inheritsInput = plan.options.json
        spec.timeout = .seconds(plan.options.maximumSeconds)
        return try await launch(spec)
    }

    private func launch(_ spec: CommandSpec) async throws -> Int32 {
        let (signals, delivered) = AsyncStream.makeStream(of: Int32.self)
        // Watching starts before the runner does, so that no signal finds it unwatched.
        let relay = SignalRelay(signals: [SIGINT, SIGTERM]) { delivered.yield($0) }
        defer { relay.stop() }
        return try await withThrowingTaskGroup(of: Outcome.self) { group in
            group.addTask {
                do {
                    return .finished(try await ProcessRunner.run(spec, output: .inherit))
                } catch is CancellationError {
                    // Only a signal cancels the group, and its own task reports the number.
                    return .signalled(0)
                }
            }
            group.addTask {
                for await number in signals { return .signalled(number) }
                return .signalled(0)
            }
            var status: Int32 = 1
            var caught: Int32?
            // A signal cancels the group, which stops the runner; the runner's end cancels the wait for a signal.
            for try await outcome in group {
                switch outcome {
                case .finished(let result):
                    status = result.timedOut ? Self.timedOutStatus : result.status
                    if result.timedOut { Output.err("stopped: the run reached --max-seconds \(plan.options.maximumSeconds)") }
                case .signalled(let number):
                    caught = caught ?? (number == 0 ? nil : number)
                }
                group.cancelAll()
            }
            return caught.map { 128 + $0 } ?? status
        }
    }
}

/// Reports SIGINT and SIGTERM (or any signals) to a handler while it is active, in place of ending this process; ``stop()``
/// gives each signal its default action back. Each signal is set to be ignored and is received through a dispatch source,
/// so no code runs in signal context.
final class SignalRelay {
    private let signals: [Int32]
    private var sources: [any DispatchSourceSignal] = []

    init(signals: [Int32], handler: @escaping @Sendable (Int32) -> Void) {
        self.signals = signals
        for number in signals {
            signal(number, SIG_IGN)
            let source = DispatchSource.makeSignalSource(signal: number)
            source.setEventHandler { handler(number) }
            source.resume()
            sources.append(source)
        }
    }

    deinit {
        stop()
    }

    /// Cancels the sources and restores the default actions. Calling it again does nothing.
    func stop() {
        guard !sources.isEmpty else { return }
        for source in sources { source.cancel() }
        sources.removeAll()
        for number in signals { signal(number, SIG_DFL) }
    }
}
```

`ContainerRun.launch` watches SIGINT and SIGTERM before the runner starts; a signal cancels the task group, which makes `ProcessRunner` stop the runner (SIGTERM, then SIGKILL after five seconds), and the status is 128 plus the signal. `--max-seconds` is `CommandSpec.timeout` (status 124).

            directory (a new private one under the temporary directory, printed; --scratch reuses one, so the kernel and the \
            image store survive between runs), runs the signed runner there with the options below, streams its standard output \
            and error through, and exits with its status. The runner pulls the image, boots a Linux virtual machine and runs \
            the command in it.

            This boots a real virtual machine. CONTRIBUTING.md ("Real-guest runs") says: "Run it only when the owner has \
            authorised real-guest runs for the session", with the guest's resources capped, so the command refuses to run \
            without --boot (as `vmr sandbox run` does), takes at most \(ContainerRunPlan.maximumCPUs) CPUs and \

            With --json the runner prints one JSON event per line on standard output and reads standard input: a `stop` line or \
            its end stops the container (status 75). The runner's own options are described by `ContainerRunner --help`. The \

                configuration: configuration ?? .release,
                plan: plan
            ).run()
        }
    }
