## Why

A Linux machine on the custom GPU had no input path: its window took the keyboard and swallowed every key. Two paths are to be compared by a run against a real guest, behind one protocol: the framework's own input (this card) and a virtio input device the app implements (the next card). A hidden developer default chooses between them; the setting in the app stays the plain Apple/Custom choice.

**The protocol.** `GuestInputSurface` (`@MainActor`, a class protocol): `attach(to:)` and `detach(from:)` with the picture's view, `placePicture(_:in:)` (where the picture sits in that view), `capturesSystemKeys` (the machine's setting), `use(machine:)` (the machine, told once when it exists), and one method for each kind of event the picture's view receives: key down and up, modifiers changed, mouse moved, dragged, down and up (with a `GuestMouseButton`: left, right, other) and scroll. Each takes the `NSEvent` itself: the framework's view needs the event, and a surface that encodes it converts the point through the view it is attached to. `CustomDisplaySource` gains `input`; `CustomGPUSession` holds the surface (the framework's by default) so that it lives as long as the machine. A surface serves one view at a time: full screen swaps the view for a new one, whose `use` moves the surface, and the old view's later `detach` changes nothing.

**The picture's view** (`CustomGPUView`, with the overrides in `CustomGPUView+Input.swift`) keeps the keyboard and receives every event, as before, and passes each to its surface once; without one it swallows them (no beep, as before). It asks for mouse moves through a tracking area of its own (a view gets `mouseMoved` without a button only that way), and tells the surface where the picture sits at each layout and each new picture (`ScreenPlacement.pictureRect`).

**The framework's path** (`FrameworkInputSurface`): a `VZVirtualMachineView` that is not shown: `virtualMachine` is the machine, `capturesSystemKeys` the setting (written only when it differs), `automaticallyReconfiguresDisplay` off (the custom device follows the window itself). The machine keeps the USB keyboard and screen-coordinate pointer the builder gave it (T09); that view is what feeds them. The picture comes from the custom device, so the view has nothing to draw.

**The developer default.** `CustomGPUInputPath`: the key `CustomGPUInput` in the app's defaults domain (`PreferencesDomain.defaults`), the values `framework` (the default) and `virtio`, anything else (absent, empty, another case, another type) meaning `framework`. `VZMachineFactory.prepare` reads it once per machine start. It is not in `AppSetting` (those are the user's settings and a test pins them), not in the interface, and not managed. The only place the repository documents a hidden default is the help topic of the custom GPU (its advanced paragraph, edited here) and roadmap 0014; CONTRIBUTING has no section of developer settings.

**Judgement calls (recorded; do not change them):**

1. **The framework's view sits BELOW the picture's view (b1), not above it (b2).** In b1 the picture's view, opaque and on top, can never be hidden by the other, which is the property that matters while nothing has run; the picture's view stays the first responder and the hit-test target, and passes the events down. In b2 the framework's view would receive events itself but would have to be transparent, and nothing is known about what it draws or what it does to the first responder with no graphics device; a layer or alpha trick would be a guess on top of a guess. b2 is not built and not kept as an option.
2. **The framework's view is placed on the picture's on-screen rectangle** (`ScreenPlacement.pictureRect`, flipped to AppKit's origin by the new `ScreenPlacement.flipped` and converted into the container's coordinates), at each layout and each new picture. The view maps a point of its bounds to the screen-coordinate pointer, so with bars around the picture a point lands on the guest pixel under it, as with the framework's own graphics device. With no picture the frame is empty. `placeCursor` uses the same `flipped`.
3. **`virtio` is read and logged but runs the framework's path in this commit.** The value is part of the default from the start; the path it names is the next card. `VZMachineFactory` logs one notice (`Log.input`) for it.
4. **The surface is told its machine by `VZGuestMachine.init`**, where the machine and the custom display are both known, rather than by the factory or the view: the view has no machine, and the sessions are made before it exists. A path that needs no framework view ignores the call. A test never makes a machine, so `use(machine:)` is checked on a real host only by the real run.
5. **Not forwarded, and not known:** key equivalents (`performKeyEquivalent`: a Command shortcut goes to the menu before it can reach the guest unless the framework's view captures it, which `capturesSystemKeys` relies on the framework's view for), mouse entered and exited, magnification and the other gestures, and focus changes (the framework's view is never first responder). Whether the framework's view needs any of them from a view that is not its window's first responder is what the real run shows. The 27.0 SDK also has `VZVirtualMachineViewAdaptor` (`VZVirtualMachineView.adaptor`); it is not used.
6. **A tracking area on the picture's view** (`.mouseMoved`, `.activeInKeyWindow`, `.inVisibleRect`) is the one addition the pointer needs beyond the events the view already got; `updateTrackingAreas` replaces it.
7. **Tests:** no existing test changes. `FakeCustomSource` (a test-support file) gains the `input` the protocol now asks for, and `ScreenPlacementTests` gains a test. `InputLatencyMonitor.holdsMachineView` is unchanged and still finds the window (a test asserts it with the surface attached).
8. **The builder is untouched:** a machine on the custom GPU keeps the USB keyboard and pointer, which the framework's view needs.

import Foundation

/// Which path carries the keyboard and pointer of a machine on the custom GPU: the framework's own input view, kept behind the
/// picture, or a virtio input device that the app implements. A developer default decides, not a setting in the app; the real
/// run against a guest is what chooses between the paths.
///
/// The value is read once, when a machine is prepared (`VZMachineFactory.prepare`), so changing it affects the next start only.
/// `defaults write <the app's bundle identifier> CustomGPUInput virtio` sets it. Any value but the two names, a value of
/// another type included, means `framework`.
enum CustomGPUInputPath: String, Sendable {
    case framework
    case virtio

    /// The key of the default in the app's defaults domain (`PreferencesDomain.defaults`).
    static let defaultsKey = "CustomGPUInput"

    init(storedValue: String?) {
        self = storedValue.flatMap(Self.init(rawValue:)) ?? .framework
    }

    static func current(in defaults: UserDefaults = PreferencesDomain.defaults) -> Self {
        Self(storedValue: defaults.string(forKey: defaultsKey))
    }
}

import AppKit
import Virtualization

/// The framework's own input for a machine on the custom GPU: a `VZVirtualMachineView` that is never shown. The machine has the
/// USB keyboard and screen-coordinate pointer of any other Linux machine, and the framework's view turns events into input for
/// them. The view has no graphics device to draw (the pixels come from the custom GPU), so it sits in the container **below**
/// the picture's view and the picture's view, which stays on top and keeps the keyboard, passes it every event. It cannot hide
/// the picture, and nothing hit-tests to it.
///
/// The framework's view maps a point of its own bounds to a position of the guest's screen, so its frame is the rectangle the
/// picture occupies on screen (`placePicture`): with bars around a picture of another shape, a point then lands on the guest
/// pixel under it. Whether the framework's view takes events passed to it this way, rather than delivered by the window, is
/// what a run against a real guest shows.
@MainActor
final class FrameworkInputSurface: GuestInputSurface {
    private let view: VZVirtualMachineView
    private weak var host: CustomGPUView?

    init(view: VZVirtualMachineView = VZVirtualMachineView()) {
        self.view = view
        // The custom GPU's display follows the window through the device (`CustomGPUResizableDisplay`), never through this view.
        view.automaticallyReconfiguresDisplay = false
    }

    var capturesSystemKeys: Bool {
        get { view.capturesSystemKeys }
        // Written only when it differs: the framework switches the property off on a view when another view of the same
        // machine switches it on.
        set { if view.capturesSystemKeys != newValue { view.capturesSystemKeys = newValue } }
    }

    func use(machine: VZVirtualMachine) {
        view.virtualMachine = machine
    }

    func attach(to host: CustomGPUView) {
        self.host = host
        view.removeFromSuperview()
        // AppKit declares `superview` unowned(unsafe); it is alive for the duration of this call and not kept.
        unsafe host.superview?.addSubview(view, positioned: .below, relativeTo: host)
    }

    func detach(from host: CustomGPUView) {
        guard self.host === host else { return }
        view.removeFromSuperview()
        self.host = nil
    }

    func placePicture(_ rect: CGRect, in size: CGSize) {
        // AppKit declares `superview` unowned(unsafe); it is alive for the duration of this call and not kept.
        guard let host, let container = unsafe host.superview else { return }
        view.frame = container.convert(ScreenPlacement.flipped(rect, in: size), from: host)
    }

    func keyDown(_ event: NSEvent) { view.keyDown(with: event) }
    func keyUp(_ event: NSEvent) { view.keyUp(with: event) }
    func flagsChanged(_ event: NSEvent) { view.flagsChanged(with: event) }
    func mouseMoved(_ event: NSEvent) { view.mouseMoved(with: event) }
    func scrollWheel(_ event: NSEvent) { view.scrollWheel(with: event) }

    func mouseDragged(_ event: NSEvent, button: GuestMouseButton) {
        switch button {
        case .left: view.mouseDragged(with: event)
        case .right: view.rightMouseDragged(with: event)
        case .other: view.otherMouseDragged(with: event)
        }
    }

    func mouseDown(_ event: NSEvent, button: GuestMouseButton) {
        switch button {
        case .left: view.mouseDown(with: event)
        case .right: view.rightMouseDown(with: event)
        case .other: view.otherMouseDown(with: event)
        }
    }

    func mouseUp(_ event: NSEvent, button: GuestMouseButton) {
        switch button {
        case .left: view.mouseUp(with: event)
        case .right: view.rightMouseUp(with: event)
        case .other: view.otherMouseUp(with: event)
        }
    }
}
