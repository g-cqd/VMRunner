# V03 — `machines.log`: a token with the log capability reads a container's output; `vmr control log`; the MCP tool `machines_log`

Model: haiku · Effort: low · Worktree: yes, `WT = ~/Developer/g-cqd/VMRunner-chains/v-containers` (branch `chain/v-containers`) · Chain: V, card 3 of 5 (after V02; next V04)

The change is the fixture patch, applied as it is: never edit code by hand; a patch that does not apply, a hash that differs or a gate that fails is a STOP. One commit, signed, atomic; `swift run vmr check` 8/8 read before it. No board ids, no outside project names, no placeholders in the repository.

Why: with the output kept in the machine's folder (previous card), a script or agent that may already start and stop a
container needs a way to read what it printed, through the same checks as the rest of the control service. The service now
exposes container output to a token holder, so the exposure line and the help say so.

Decisions:
- ControlProtocol: `ControlCapability.log` (label "Read a container's log"); `ControlMethod.log = "machines.log"` with params
  `token` and `machine`; `ControlLog` (`id`, `text`, `truncated`; `maxBytes = 65_536`; `end(of:bytes:)` cuts forward to a
  character); `ControlLogOutcome` (`text(_:truncated:)` or `refused(_:)`); `ControlMachines` gains the requirement
  `log(_:)` (no default implementation, so every conformer says what it does).
- The dispatcher checks a log call exactly as a state call (method, params, token, capability, scope, machine exists, agent
  access) and cuts the text to 64 KiB again whatever the adapter returned; a refusal is -32004. Params stay strings and
  booleans: the method takes no size.
- `LibraryControlMachines.log`: organisation off → the closed refusal; agent access off → refused; a virtual machine →
  "This machine is not a container; only a container machine keeps an output log."; otherwise the tail of the output files,
  read off the main actor (`@concurrent`).
- `ContainerExposures`: with agent access on, a second line after the agent-access one: "Container output: a script or AI
  agent whose control token has the log capability can read the last 64 KiB of what this container printed while the
  control service is on." (`Security.swift` is not touched.)
- `vmr control log MACHINE [--bytes N] [--json]`: N from 1 to 65536 (default 65536; outside, or a size with `--json`, is a
  usage error, exit 64); prints the end of the text, first `[earlier output not shown]` when the service or `--bytes` cut it;
  a token without the capability exits 77; a VM's refusal exits 1.
- MCP: `machines_log` (read-only hints), third in the list; it answers the service's JSON like the other tools.
- Help (agent access, control service, control tokens, containers), README and CONTRIBUTING's `vmr control` lines updated.

**Existing tests that change, on purpose:** `Tests/AgentBridgeTests/MCPServerTests.swift`: the tools/list expectation gains
`machines_log` and the test is renamed `theToolsAreTheFiveControlMethodsWithStrictSchemas` (its other assertions, on the
last tool `machines_stop`, are unchanged). The test conformers of `ControlMachines` (`FakeMachines`, `StaticMachines`,
`MemoryMachines`, `TwoMachines`) gain `log`; `FakeMachines` answers a short text, so `eachMethodNeedsItsOwnCapability`
covers the new method unchanged. Any OTHER existing test that fails is a STOP.

New tests: `Tests/ControlProtocolTests/ControlLogTests.swift` (capability, scope, agent access, missing machine, refusal,
the 64 KiB cut, the character cut, the worst-case escaping round trip through a connection and a client, the token file),
`Tests/DevToolsTests/ControlLogCommandTests.swift` (text, `--bytes`, usage errors, `--json`, exit 77), and additions in
`ContainerControlTests`, `ControlServiceTests`, `ControlTokensModelTests`, `MCPStdioTests` and `MCPServerTests`.
