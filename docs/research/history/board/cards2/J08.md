Why: ADR-0056 decision 1. The service runs only while the user turned it on in Settings. The switch is an app setting,
`runsControlService` (false by default), added the way the other app settings are (`AppSetting`, `@AppStorage` in
`SettingsView`, `.managedLock`, the list in the help on managed settings). An organisation turns the whole feature off with
a new managed key, added the way the other `Allow…` keys are (ADR-0013): `AllowControlService` forced to anything but
`true` denies it; `clamp` then turns agent access off on every machine (the library applies `clamp` to every machine it
loads, adds and changes), and both the Settings switch and the machine's switch show the lock. The switch is read by the
service in J10; until then it is stored and shown only.

## Test

The two new `ManagedPreferencesTests` are the acceptance of the key: a forced `false`, a string and a number all deny it
(wrong types restrict), lock it, and clamp agent access off; a forced `true` allows it; nothing forced changes nothing; the
app setting locks when forced. The existing `theHelpNamesEveryKeyThatCanBeManaged` now requires `AllowControlService` and
`runsControlService` in the help, and `AppSettingTests` pins the stored key name. `HelpCatalogTests` check the new topic.
