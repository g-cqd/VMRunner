Why: ADR-0012 decision 1: "a read-only `cidata` volume attached as USB mass storage". INDEX-L decision 1 says why USB and
not a read-only virtio disk: cloud-init's NoCloud source finds the volume by its label on any block device, the app already
boots every catalog installer from a read-only USB drive, the guest's virtio disks stay the user's own, and a USB device is
the one that can later be detached while the machine runs. The seed takes the installer's place: `activeProvisioningSpecPath`
is nil while the installer is attached (L01), so the two are never attached together. A missing seed file fails the build
(as a missing installer does) instead of starting without it. Building the devices only opens the files, so the tests run
without a machine.

## Test

`StorageDevicesTests`: with a spec in use the seed is the third device, USB, read-only, the bundle's `ProvisioningSeed.iso`;
without the file the build throws `SetupError`; a macOS guest gets no seed; with the installer attached the USB drive is the
installer. `ProvisioningSeedTests.theSeedAStartWritesIsTheReadOnlyDriveTheMachineGets` wires the two halves: the file the
start writes (a real spec compiled by the library) is the read-only drive the configuration attaches. The existing
`aHardenedLinuxMachineGetsOnlyItsOwnDisk` and the installer tests must pass unchanged.
