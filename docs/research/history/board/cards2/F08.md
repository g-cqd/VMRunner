Why (read from the code): `VZGuestMachine.setNetworkConnected(false)` sets `device.attachment = nil` and assumes it took.
The framework reports a refused change to its delegate; if it ever left the attachment in place, the toolbar would show
"Network cut" over a live link: the kill switch would fail open. After this card the cut is read back at once: a card that
still has an attachment makes the machine stop, with a message, and the log says why.

**Owner decision pending, default implemented: stop the machine** (fail closed). The alternative is to keep the machine
running and only show an error. This card writes the default into the code, the help and roadmap 0010 ("Owed"), and says
there that it waits for the owner. The other question of the review, cutting the card **before** the machine starts (today
the cut follows `machine.start()`), needs a real guest: it is only recorded in 0010 as part of the owed run. No card starts
a machine.

Testability: the pull and the read-back move into a small value, `NetworkCardCable`, that works on any `NetworkCard` (a
protocol with the one property the kill switch uses, `attachment`). `VZNetworkDevice` conforms as it is; the test uses a
fake card that refuses to let go of its attachment.

/// The part of a machine's network card the kill switch changes: its attachment, the cable.
@MainActor
protocol NetworkCard: AnyObject {
    var attachment: VZNetworkDeviceAttachment? { get set }
}

extension VZNetworkDevice: NetworkCard {}

/// The cable of a machine's network card as the kill switch pulls it: it keeps the attachment it took off to put the same
/// one back, and reads the card back after a pull, so a pull that did not take is reported, never assumed.
@MainActor
struct NetworkCardCable {
    private var detached: VZNetworkDeviceAttachment?

    /// Takes the attachment off `card` (`connected` false) or puts back the one it had (`true`). Returns false when the card
    /// still has an attachment after it was set to nil: the change was refused, and the guest is still connected.
    mutating func set(_ card: some NetworkCard, connected: Bool) -> Bool {
        if connected {
            guard let attachment = detached else { return true }
            card.attachment = attachment
            detached = nil
            return true
        }
        guard let attachment = card.attachment else { return true }
        detached = attachment
        card.attachment = nil
        return card.attachment == nil
    }
}
```

    /// Takes the attachment off the network card (`false`) or puts the one it had back (`true`), like pulling and
    /// replugging a cable. A pull is read back at once: a card that is still connected stops the machine.
    private func setNetworkConnected(_ connected: Bool) {
        guard let device = machine.networkDevices.first else { return }
        if !cable.set(device, connected: connected) { stopBecauseTheCutFailed() }
    }

    /// Fails closed when the network card kept its attachment after the kill switch took it off: the guest must not keep
    /// running behind a toolbar that says its network is cut. Stopping is the default until the owner decides between
    /// stopping and only showing an error (roadmap 0010, "Owed").
    private func stopBecauseTheCutFailed() {
        Log.machine.error("The network card stayed connected after the kill switch cut it; stopping the machine")
        Task { [weak self, machine] in
            try? await machine.stop()
            self?.onStoppedWithError?(Self.cutFailedMessage)
        }
    }

/// The cable the kill switch pulls: the same attachment goes back, and a pull the card refuses is reported, never assumed.
@MainActor
struct NetworkCardCableTests {
    /// A card whose attachment the test controls; `refusesDetach` makes it keep its attachment, as a refused change would.
    @MainActor
    private final class FakeCard: NetworkCard {
        var refusesDetach = false
        private var current: VZNetworkDeviceAttachment?

        init(_ attachment: VZNetworkDeviceAttachment?) { current = attachment }

        var attachment: VZNetworkDeviceAttachment? {
            get { current }
            set { if newValue != nil || !refusesDetach { current = newValue } }
        }
    }

    @Test func aPulledCableIsPluggedBackWithTheSameAttachment() {
        let nat = VZNATNetworkDeviceAttachment()
        let card = FakeCard(nat)
        var cable = NetworkCardCable()
        let pulled = cable.set(card, connected: false)
        #expect(pulled)
        #expect(card.attachment == nil)
        let pluggedBack = cable.set(card, connected: true)
        #expect(pluggedBack)
        #expect(card.attachment === nat)
    }

    @Test func aPullTheCardRefusesIsReportedSoTheMachineCanBeStopped() {
        let nat = VZNATNetworkDeviceAttachment()
        let card = FakeCard(nat)
        card.refusesDetach = true
        var cable = NetworkCardCable()
        let pulled = cable.set(card, connected: false)
        #expect(!pulled, "the card is still connected")
        #expect(card.attachment === nat)
    }

    @Test func theHelpSaysAMachineWhoseCardStaysConnectedIsStopped() {
        #expect(HelpTopic.killSwitch.entry.advanced.joined(separator: " ").contains("VMRunner stops the machine"))
    }
}
```
