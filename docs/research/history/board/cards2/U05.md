## Decisions (read before editing; each is written so a reviewer can disagree with it)

1. **Platform and boot.** `genericPlatform(for:bundle:)` and `efiBootLoader(for:bundle:secureBoot:)` (new file `ConfigurationBuilder+GenericPlatform.swift`) hold what `configureLinux` did inline: the machine identifier (read if the bundle has one), nested virtualization, the variable store and its Secure Boot state. `configureLinux` now calls them (same behaviour, so Linux and Windows do not share an exact clone); `applySecureBoot` moved with them. Windows passes `secureBoot: false`, which also turns it off in a store that had it on.
2. **Screen and input.** Windows calls the existing `configureLinuxScreen(..., customGPU: nil)`: the framework's virtio graphics device at the configured size, a USB keyboard and the USB screen-coordinate pointer. The generic platform has no other pointing device, so "the config's pointing device" (`.mouse`) is that one; the trackpad is a Mac device. The function's name still says Linux (its tests call it): rename it in a later change, not here. Its doc comment now says Linux or Windows.
3. **Everything the other guests share is reused as it is:** `storage(for:bundle:)` (NVMe through `usesNVMeMainDisk`, the installer as read-only USB through `attachedInstallerPath`, the driver disc after it through the new `driverDisc(for:)`), `network(for:)` (virtio, NAT, bridged or filtered per mode), `sound(for:)` (the setting; off by default for Windows), entropy, balloon and vsock devices.
4. **No serial console, no seed, no Rosetta, no clipboard agent.** The builder's existing guards (`guest == .linux`) already make these no-ops for Windows, and `validate()` refuses the settings; a test builds a Windows configuration that asks for all of them and gets none.
5. **Shared folders: no tag of its own, no special case.** `directoryShares` attaches the shared device with the generic tag (`share`) whatever the non-macOS guest; for Windows that device is inert unless the guest installs a virtio file-system driver of its own. This card adds nothing for it (the previous card hides the Linux mount hint for Windows). Shared folders stay approvable and listed in the exposure summary like any other guest's.
6. **The driver disc** is a second read-only USB drive after the installer, for Windows only (`attachedDriverDiscPath`), approved by its own grant kind `driverDisc` ("driver disc, read-only"; a distinct kind so the approval prompt does not call a driver image an installer). It is a host channel like an extra disk, so: absolute path and length at decode, not inside the Machines folder (decode and build), existing at build, closed by Isolated and Hardened (the profile clears the path, as it clears extra disks) and counted by the profile posture, listed in the exposure summary. Unlike the installer there is no "attached" switch: it is there while its path is set.
7. **The emulation.** `WindowsStartSettings.current(for:)` is read once for a start in `VZMachineFactory.prepare` (where `CustomGPUInputPath.current()` is read), from the configuration the start uses: the policy decision (`PrivateCapabilityPolicy.decide` with the machine's detected profile, the managed preferences and the kill switch `DisablePrivateInterfaces`), and the developer default. `configureWindows` creates the platform, then: policy denies -> start error with the policy reason, the capability is not asked; policy allows -> `PMUEmulation.apply(to:in:registry:)` through `applyPerformanceMonitoring`; unavailable -> start error with the capability module's reason. A build called without settings (`windows: nil`) reads this Mac's own, so nothing can skip the policy. The closure makes the tests deterministic: they never call the private switch.
8. **The developer default only relaxes a refusal.** `WindowsStartsWithoutPMU` true: when the emulation is denied or unavailable the machine starts without it and `Log.machine` records one notice naming the capability, the reason and the key; when the emulation can be used it is still turned on (the default does not switch a working capability off). Only an explicit `true` of type Bool counts (absent, false, strings and other types leave the start refused). It is developer-only: no setting in the app, no help in this card (the help card documents the key beside `DisablePrivateInterfaces`).
9. **Setup at creation.** A Windows machine is installed by booting the installer image, so `Provisioner.run` sends `.windows` down the Linux ISO-install path (renamed `provisionInstallerMachine`): it makes the folder and the sparse disk, keeps the chosen local image as the installer (a file the user picked stays where it is), creates the EFI variable store and writes a generic machine identifier. Nothing in it is specific to a catalog download. The Windows source is a local file, which the next card enforces in the sheet; this card does not add a check for a hand-edited remote source (follow-up).
10. **Nested virtualization.** The previous card refused it on Windows. The owner wants Windows to run with all possible features, so the refusal is removed: `validateGuest()` no longer lists it, the builder honours it through the shared `genericPlatform` (a host that cannot do it fails the start with `SetupError.unsupportedHost`, as for Linux), and the posture and the exposure summary count it for every generic-platform guest (`guest.usesGenericPlatform`, not only Linux) so a Windows machine with it on is listed and does not read as Contained. Default off.
11. **Suspend.** Windows reports none (`guestSuspendReason`, card 4); the exposure summary says no memory snapshot is written. Unchanged here.

## Test fixtures (an edit of existing tests, stated; no assertion changes)

Four existing tests stood in for a machine's firmware variables with made-up bytes (`Data("nvram".utf8)` written to `EFIVariables.fd`). Until this card nothing in them asked the framework about that file. Now `ConfigurationBuilder.efiBootLoader` sets Secure Boot on the store (`applySecureBoot`, which reads `isSecureBootEnabled`), and from the first time the framework is asked about a file that is not a store, every later `VZEFIVariableStore` operation in the same test process fails with `Failed to initialize the variable store. EFI error: 0x8000000000000014` and does not recover. Which tests then failed depended on the order the runner picked (`WindowsBuilderTests`, `WindowsMediaTests`; 10 of 15 full runs failed before the fix). The fix is in the fixtures only: `TestSupport.swift` gets `writeEFIVariableStore(at:)`, which creates a real empty store with `VZEFIVariableStore(creatingVariableStoreAt:options: [.allowOverwrite])`, and the three tests that wrote the fake bytes (`ConfigurationBuildTests`, `ControllerRig`, `GuestIdentityTests`) call it instead. The other tests that write the same fake bytes never reach the builder (they clone, duplicate or snapshot the file) and are left as they are. No test's assertion changes. No production code changes. A production consequence (a start that finds a damaged store makes the framework unusable for the rest of the process) is not addressed here: it is a follow-up for the owner.

import Virtualization

extension ConfigurationBuilder {
    /// The generic platform of a Linux or Windows guest: the machine's identifier, when its bundle has one, and nested
    /// virtualization when the machine asks for it and the host can do it.
    static func genericPlatform(for config: VMConfig, bundle: VMBundle) throws -> VZGenericPlatformConfiguration {
        let platform = VZGenericPlatformConfiguration()
        if let data = try? Data(contentsOf: bundle.activeMachineIdentifier(ephemeral: config.ephemeral)),
            let identifier = VZGenericMachineIdentifier(dataRepresentation: data)
        {
            platform.machineIdentifier = identifier
        }
        if config.nestedVirtualization {
            guard VZGenericPlatformConfiguration.isNestedVirtualizationSupported else {
                throw SetupError.unsupportedHost("Nested virtualization needs an M3 or newer chip.")
            }
            platform.isNestedVirtualizationEnabled = true
        }
        return platform
    }

    /// The EFI boot loader of a Linux or Windows guest, with the machine's variable store set to `secureBoot`.
    static func efiBootLoader(for config: VMConfig, bundle: VMBundle, secureBoot: Bool) throws -> VZEFIBootLoader {
        let variableStore = VZEFIVariableStore(url: bundle.activeEFIVariables(ephemeral: config.ephemeral))
        try applySecureBoot(secureBoot, to: variableStore)
        let boot = VZEFIBootLoader()
        boot.variableStore = variableStore
        return boot
    }

    /// Enrolls the Apple platform key and Microsoft's UEFI keys (so Microsoft-signed distro shims, like
    /// CentOS's, still boot) and turns enforcement on or off to match the setting.
    private static func applySecureBoot(_ wanted: Bool, to store: VZEFIVariableStore) throws {
        guard #available(macOS 27.0, *) else {
            if wanted { throw SetupError.unsupportedHost("Secure Boot needs macOS 27 or later on the host.") }
            return
        }
        let enabled = (try? store.isSecureBootEnabled) ?? false
        if wanted, !enabled {
            try store.enrollDefaultSecureBootSignatures()
            try store.enableSecureBootUsingDefaultPlatformKey()
        } else if !wanted, enabled {
            try store.disableSecureBoot()
        }
    }
}

### `Sources/VMRunner/Engine/ConfigurationBuilder+Windows.swift` (new)

Create it with exactly:

```swift
import Foundation
import PrivateInterfaces
import Virtualization
import os

extension ConfigurationBuilder {
    /// A Windows guest: the generic platform with the EFI boot loader (Secure Boot off), the framework's graphics device and
    /// its USB keyboard and pointer. The NVMe main disk, the installer and the driver disc, the network and the sound come from
    /// the devices every guest shares. It has no serial console, no cloud-init seed and no Rosetta, and no guest agent: the
    /// clipboard setting is inert for it. Shared folders are not special-cased: they use the shared device and tag, which
    /// a Windows guest sees only with a virtio file system driver of its own.
    ///
    /// The machine needs the performance-monitoring emulation to boot Windows. It is turned on through the capability module
    /// when the policy allows it; when the policy denies it or the capability is unavailable, the start fails with a message
    /// that names the capability and why, unless the developer default lets the machine start without it.
    static func configureWindows(
        _ vz: VZVirtualMachineConfiguration, _ config: VMConfig, _ bundle: VMBundle, _ display: (width: Int, height: Int),
        settings: WindowsStartSettings
    ) throws {
        let platform = try genericPlatform(for: config, bundle: bundle)
        try requirePerformanceMonitoring(on: platform, settings: settings)
        vz.platform = platform
        vz.bootLoader = try efiBootLoader(for: config, bundle: bundle, secureBoot: false)
        try configureLinuxScreen(vz, config, display, customGPU: nil)
    }

    /// Turns the emulation on for `platform`. A reason it is off ends the start, or is logged once when the developer default
    /// asks to start anyway.
    private static func requirePerformanceMonitoring(
        on platform: VZGenericPlatformConfiguration, settings: WindowsStartSettings
    ) throws {
        let capability = PrivateCapabilityID.performanceMonitoringEmulation
        let reason: String
        switch settings.decision {
        case .denied(let denial):
            reason = denial.description
        case .allowed:
            guard case .unavailable(let unavailable) = settings.applyPerformanceMonitoring(platform) else { return }
            reason = unavailable.description
        }
        guard settings.startsWithoutPerformanceMonitoring else {
            throw SetupError.requiredCapabilityUnavailable(guest: .windows, capability: capability.title, reason: reason)
        }
        let (name, key) = (capability.title, WindowsStartsWithoutPMU.defaultsKey)
        Log.machine.notice(
            "Windows starts without the \(name, privacy: .public) (\(reason, privacy: .public)): \(key, privacy: .public) is on")
    }

    /// The driver disc of a Windows machine as a read-only USB drive, or nil when it has none. A file the guest reads whole is
    /// a host channel like an extra disk: it must exist and must not be a file inside the Machines folder.
    static func driverDisc(for config: VMConfig) throws -> VZUSBMassStorageDeviceConfiguration? {
        guard let path = config.attachedDriverDiscPath else { return nil }
        guard !AppPaths.isInside(URL(filePath: path), AppPaths.machines) else { throw HostPathError.insideMachinesFolder(path) }
        guard FileManager.default.fileExists(atPath: path) else { throw SetupError.missingFile(path) }
        let attachment = try VZDiskImageStorageDeviceAttachment(url: URL(filePath: path), readOnly: true)
        return VZUSBMassStorageDeviceConfiguration(attachment: attachment)
    }
}
```

/// The developer default that lets a Windows machine start although its performance-monitoring emulation is off or
/// unavailable: `defaults write <the app's bundle identifier> WindowsStartsWithoutPMU -bool true`. It is for watching what
/// Windows does without it, not a setting in the app. It is read once when a machine starts, so a change affects the next start
/// only. Only an explicit true turns it on: an absent key, a false and a value of any other type leave the start refused.
enum WindowsStartsWithoutPMU {
    static let defaultsKey = "WindowsStartsWithoutPMU"

    static func isOn(in defaults: UserDefaults = PreferencesDomain.defaults) -> Bool {
        (defaults.object(forKey: defaultsKey) as? Bool) == true
    }
}

/// What a Windows start decides about its private interface before the builder runs, read once when the machine is prepared
/// (`VZMachineFactory.prepare`) and handed to the builder: whether the policy allows the interface, how to turn it on for a
/// platform configuration, and whether the developer default lets the machine start without it. A test states each of them.
struct WindowsStartSettings: Sendable {
    var decision: PrivateCapabilityPolicy.Decision
    var applyPerformanceMonitoring: @Sendable (VZGenericPlatformConfiguration) -> PrivateCapabilityStatus
    var startsWithoutPerformanceMonitoring: Bool

    /// The settings of this Mac and this app for `config`, which is the configuration the start uses (managed keys applied).
    static func current(
        for config: VMConfig, managed: ManagedPreferences = .current, defaults: UserDefaults = PreferencesDomain.defaults,
        context: PrivateCapabilityContext = .current(), registry: CapabilityRegistry = .standard
    ) -> Self {
        Self(
            decision: PrivateCapabilityPolicy.decide(
                posture: config.detectedProfile, managed: managed, killSwitch: PrivateInterfacesKillSwitch.isOn(in: defaults)),
            applyPerformanceMonitoring: { PMUEmulation.apply(to: $0, in: context, registry: registry) },
            startsWithoutPerformanceMonitoring: WindowsStartsWithoutPMU.isOn(in: defaults))
    }
