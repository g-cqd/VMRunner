## Why

ADR-0056 left screenshots undecided ("What this does not decide"). A machine on the custom GPU draws into a `CustomScreen` the app already holds, so an agent can read the picture without ScreenCaptureKit, a private selector or AppKit. Decided design (do not change it):

1. **A sixth capability, `screen`** (after `log`; raw value `screen`, label "Read screen"). A token holds only what its creator ticked; the Settings sheet lists `ControlCapability.allCases`, so the toggle appears with no view change and starts off.
2. **A sixth method, `machines.screenshot`** (params `token`, `machine`). Result `{id, width, height, format:"png", data:<base64>}`. `ControlMachines` gains `screenshot(_:) async -> ControlScreenshotOutcome`. The dispatcher's token, capability, scope and agent-access checks are unchanged; it only dispatches the new case.
3. **The app adapter** (`LibraryControlMachines.screenshot`) has the same organisation and agent-access guards as start and stop, refuses a machine that is not running, and reads `(controller.guest as Any as? any GuestMachine)?.customDisplay?.screen.frame` (the same cast `MachineModel.customDisplay` uses). A machine without a custom display (the framework's view, macOS guests, containers) is refused with "Screenshots need the custom GPU for now."; a custom display that has drawn nothing yet is refused with a sentence.
4. **Size bound.** The client rejects an answer line over 1 MiB (`ControlClient.defaultAnswerBytes`). `ScreenshotPNG` makes the picture at most 1280 pixels on its longest side and keeps the PNG at or under `ControlScreenshot.maximumBytes` (700,000 bytes; base64 makes it 933,336 characters, leaving about 115 KB for the rest of the line). Content that does not compress (noise) is scaled down in steps (1280, 960, 640, 480, 320 on the longest side) until it fits. The last step cannot exceed 320 x 320 x 4 bytes of pixels, about 410 KB even stored uncompressed, so a picture always fits; a test computes this. The dispatcher's encoder now writes slashes unescaped (`.withoutEscapingSlashes`): base64 holds `/`, and an escaped one costs a byte each, which would double the worst case. No existing answer changes in meaning.
5. **MCP.** Tool `machines_screenshot` (read-only hint true); its result is MCP image content (`type: image`, `mimeType: image/png`, base64 `data`) plus a text content with the size. `MCPServer.imageResult` builds it; `MCPStdio.run` turns the service's screenshot answer into it.
6. **CLI.** `vmr control screenshot <machine> --output FILE` writes the PNG (atomic write, mode 0600, relative to the current directory) and prints one line; `--json` prints the service's answer instead and writes nothing; giving neither or both is a usage error (64). A file that cannot be written exits 73.
7. **Exposure.** `agentAccessExposure` no longer says only host-side: it says a token with the Read screen capability can read the picture of the screen of a machine that uses the custom GPU. `AgentAccessTests` pins the new text. Help (*Agent access*, *Control service*, *Control tokens*) and ADR-0056 (an update paragraph) say the same.
8. **Downgrade.** `ControlToken` decoded a capability set strictly, so one unknown capability made the whole token file unreadable (the store then refuses it, and keeps it). Decoding now leaves out a capability this version does not know (a small change: a private `Stored` shape and one `init(from:)`), with a test. Versions before this card still refuse a file that holds `screen` (as they do one that holds `log`); the ADR update says so and how to recover.
9. **Next to the `log` capability** (already on `8fdeccf`). `screen` is appended after `log` in `ControlCapability` (Settings lists `log`, then `screen`); `ControlMethod` and `MCPTool` get `screenshot` appended, so `tools/list` answers `machines_list`, `machines_state`, `machines_log`, `machines_start`, `machines_stop`, `machines_screenshot`; `LibraryControlMachines.screenshot` reuses the `closedMessage` constant the `log` method introduced; the ADR-0056 paragraph follows the `log` paragraph; every `ControlMachines` conformer (`FakeMachines`, `MemoryMachines`, `StaticMachines`, the stdio test's `TwoMachines`, `LibraryControlMachines`) has both `log` and `screenshot`. A container with agent access on lists the agent-access exposure (now with the screen sentence, conditional on a machine that uses the custom GPU) and the container output exposure.

Not done (follow-ups): the roadmap 0005 text still says "window capture"; a screenshot of a machine on the framework's graphics device (it needs the view, which is AppKit); a ticked-`screen` warning in the Settings sheet.

```swift
import ControlProtocol
import CoreGraphics
import Foundation
import ImageIO
import UniformTypeIdentifiers
import VirtioGPU

/// A PNG of the guest's screen for the control service. The longest side is at most `longestSide`; a picture whose PNG is
/// still longer than `maximumBytes` (noise does not compress) is made smaller in steps, so the answer always fits the longest
/// line a client accepts. The last step is 320 pixels on its longest side: at most 320 × 320 × 4 bytes of pixels, about 410 KB
/// as a PNG at worst, under the default `maximumBytes`.
enum ScreenshotPNG {
    /// A PNG and its size in pixels.
    struct Picture: Equatable {
        let width: Int
        let height: Int
        let data: Data
    }

    static let longestSide = 1280
    private static let steps = [1.0, 0.75, 0.5, 0.375, 0.25]

    /// The PNG of `frame`, or `nil` for a picture `ScreenPicture` cannot make an image of or one that cannot be encoded.
    static func picture(
        of frame: ScanoutUpdate, longestSide: Int = Self.longestSide, maximumBytes: Int = ControlScreenshot.maximumBytes
    ) -> Picture? {
        guard let image = ScreenPicture.cgImage(frame) else { return nil }
        for step in steps {
            let side = max(Int((Double(longestSide) * step).rounded()), 1)
            guard let scaled = scaled(image, longestSide: side), let data = png(scaled), data.count <= maximumBytes else { continue }
            return Picture(width: scaled.width, height: scaled.height, data: data)
        }
        return nil
    }

    /// `image` itself when its longest side is at most `side`, otherwise a copy drawn at that size with its proportions.
    private static func scaled(_ image: CGImage, longestSide side: Int) -> CGImage? {
        let longest = max(image.width, image.height)
        guard longest > side else { return image }
        let factor = Double(side) / Double(longest)
        let width = max(Int((Double(image.width) * factor).rounded()), 1)
        let height = max(Int((Double(image.height) * factor).rounded()), 1)
        guard let space = CGColorSpace(name: CGColorSpace.sRGB) else { return nil }
        // Unsafe only through the type of `data`, which is nil here: the framework allocates the bitmap.
        let context = unsafe CGContext(
            data: nil, width: width, height: height, bitsPerComponent: 8, bytesPerRow: 0, space: space,
            bitmapInfo: CGImageAlphaInfo.noneSkipLast.rawValue)
        context?.interpolationQuality = .high
        context?.draw(image, in: CGRect(x: 0, y: 0, width: width, height: height))
        return context?.makeImage()
    }

    private static func png(_ image: CGImage) -> Data? {
        let data = NSMutableData()
        guard let destination = CGImageDestinationCreateWithData(data, UTType.png.identifier as CFString, 1, nil) else { return nil }
        CGImageDestinationAddImage(destination, image, nil)
        return CGImageDestinationFinalize(destination) ? data as Data : nil
    }
}
```

```swift
/// The guest's pixels as the PNG an agent reads: its colors, its size, and a length the control service can always answer.
struct ScreenshotPNGTests {
    private struct Color {
        let red: UInt8
        let green: UInt8
        let blue: UInt8
    }

    /// A frame of `width` × `height` pixels, each one `color(x, y)`, in the order of `.b8g8r8x8`.
    private func frame(_ width: Int, _ height: Int, color: (Int, Int) -> Color) -> ScanoutUpdate {
        var pixels = [UInt8](repeating: 0, count: width * height * 4)
        for y in 0..<height {
            for x in 0..<width {
                let shade = color(x, y)
                let offset = (y * width + x) * 4
                pixels[offset] = shade.blue
                pixels[offset + 1] = shade.green
                pixels[offset + 2] = shade.red
            }
        }
        return ScanoutUpdate(width: UInt32(width), height: UInt32(height), format: .b8g8r8x8, pixels: pixels)
    }

    /// A frame of bytes that do not compress, from a fixed seed, so every run encodes the same picture.
    private func noise(_ width: Int, _ height: Int) -> ScanoutUpdate {
        var state: UInt64 = 0x9E37_79B9_7F4A_7C15
        let pixels = (0..<(width * height * 4)).map { _ -> UInt8 in
            state ^= state << 13
            state ^= state >> 7
            state ^= state << 17
            return UInt8(truncatingIfNeeded: state >> 24)
        }
        return ScanoutUpdate(width: UInt32(width), height: UInt32(height), format: .b8g8r8x8, pixels: pixels)
    }

    private func decode(_ data: Data) throws -> CGImage {
        let source = try #require(CGImageSourceCreateWithData(data as CFData, nil))
        return try #require(CGImageSourceCreateImageAtIndex(source, 0, nil))
    }

    /// The red, green and blue of the pixel at `x`, `y`, read by drawing the image into an sRGB bitmap.
    private func channels(of image: CGImage, x: Int, y: Int) throws -> [Int] {
        let space = try #require(CGColorSpace(name: CGColorSpace.sRGB))
        // Unsafe only through the type of `data`, which is nil here: the framework allocates the bitmap.
        let context = try #require(
            unsafe CGContext(
                data: nil, width: image.width, height: image.height, bitsPerComponent: 8, bytesPerRow: 0, space: space,
                bitmapInfo: CGImageAlphaInfo.premultipliedLast.rawValue))
        context.draw(image, in: CGRect(x: 0, y: 0, width: image.width, height: image.height))
        let drawn = try #require(context.makeImage())
        let bytes = try #require(drawn.dataProvider?.data as Data?)
        let rowBytes = drawn.bytesPerRow
        let offset = bytes.startIndex + y * rowBytes + x * 4
        return bytes[offset..<(offset + 3)].map { Int($0) }
    }

            let color = colors[y * 2 + x]
```

```markdown
answer line always stays under the client's 1 MiB limit; the service now writes slashes unescaped for the same reason. A
machine with the framework's own graphics, a macOS guest, a container and a machine that is not running are refused with a
sentence. The checks are those of the other methods: the token, its capability, its machines and the machine's agent
access, and the organisation's switch. This changes the exposure of agent access, which no longer stops at the host: a token
with `screen` reads what the guest shows, so the machine's exposure line says so. The MCP tool `machines_screenshot` returns
the picture as image content, and `vmr control screenshot` writes it to a file only the user can read. A token file that
names a capability a version does not know now loads without it instead of failing; versions before this update refuse a
file that holds `screen`, as the update above says they do for `log`, and keep it unchanged, so remove the token or the
capability by hand to use them. The status
```
