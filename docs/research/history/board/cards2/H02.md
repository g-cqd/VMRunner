# H02 — A disposable run's fresh MAC address is not saved into the machine

Model: haiku · Effort: low · Worktree: yes, `WT = ~/Developer/g-cqd/VMRunner-chains/h-macos` (branch `chain/h-macos`, created from `main` at `471c681`) · Chain: H
Read `cards/COMMON.md` first. Anchors: locate every edit by its text (`grep -nF`), never by a line number. One commit, signed, atomic; `swift run vmr check` 8/8 before it. No board ids, no outside project names in code, docs, comments or commit messages.


Why (same run): `VMController.start` gives a disposable machine with a fresh identity a new MAC address and calls `library.update(config)`; the later `library.update(config)` for the remembered display size saves it again. After the disposable runs, the normal (non-disposable) start of the same machine used `f2:c8:9c:45:8d:ee`, the address of the last disposable run: that links the permanent machine to a run meant to be unlinkable. A machine that has no stored address must still be given one and keep it (saved state needs a stable address).

- **Files:** `Sources/VMRunner/Engine/VMController.swift` (`start`), `Tests/VMRunnerTests/` (the controller tests with a fake `MachineStore`; find with `grep -rln "MachineStore" Tests`), `docs/roadmap/0012-*.md` (a dated line), the help entry of the fresh-identity switch (`grep -rn "freshIdentityPerStart" Sources/VMRunner/Help`).

## Change
1. In `start`, before the MAC block, add `let storedMACAddress = config.macAddress`. Replace the block by:
   - if `config.networkMode.hasNetworkDevice, config.needsNewMACAddress`: set `config.macAddress = config.macVendor.makeAddress()`; call `library.update(config)` only when the machine is **not** disposable-with-fresh-identity, i.e. `!(config.ephemeral && config.freshIdentityPerStart)`.
   - Every later `library.update(config)` in `start` (the remembered display size) must save the config with `macAddress` put back to `storedMACAddress` when this start took a fresh disposable address. Implement with one small private method `persistable(_ config: VMConfig, storedMACAddress: String?) -> VMConfig` on `VMController` (or a local closure) used at those call sites; do not change the config the machine boots with.
   Read the whole `start` and any other `library.update` it reaches first; there must be no remaining path that saves the fresh address.
2. Tests (fake store records every `update`): (a) a disposable machine with a fresh identity and stored address A boots with an address B ≠ A and no `update` the test saw carries B; (b) a non-disposable machine with no stored address is given one that IS saved, and the next start reuses it; (c) a non-disposable machine with a stored address keeps it and sees no address change in `update`.
3. Help entry of the fresh-identity switch: add "The fresh address is used for that run only; the machine's own address is not changed." Roadmap 0012: dated line "2026-10-22: a real run showed a disposable run's address saved into the machine; fixed: it is used for the run only."
