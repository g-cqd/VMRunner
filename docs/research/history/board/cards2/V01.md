Why (first real run, 2026-10-25): a stop of a running container took 72.4 s to reach `stopped`; the design is a stop line,
SIGTERM after 10 s and SIGKILL 5 s later. With fake runners the driver meets 10.3 s and 15.7 s. The best-supported candidate,
unproven: macOS App Nap coalesced the main-actor timers that carry the escalation, because a container workload held no
activity (a machine with a screen holds the latency activity; a container has no screen) and the app, launched directly, was
never activated. Nothing logged where the time went.

Decisions:
- `ContainerWorkload` takes `host: any ActivityHost = ProcessInfo.processInfo` (the protocol already exists in
  `Engine/LatencyActivity.swift`). It begins one activity, `activityOptions = .userInitiatedAllowingIdleSystemSleep` (not
  latency-critical; the Mac still sleeps when idle), with `activityReason`, right after `process.start()` returned; a start
  that throws holds nothing. It ends it first thing in `ended(_:)`, and an `isolated deinit` ends a held one (a workload
  released mid-run). Both ends clear the value first, so the activity is never ended twice.
- `Log.container` (new category `container`). `ContainerProcess` logs at `info`, with the runner's pid and nothing else
  that is not a number or a boolean (`privacy: .public`; no path, no container text): the stop line written and when SIGTERM
  is due; SIGTERM and SIGKILL of the escalation, each with whether the runner still ran; a kill; the runner's exit (status,
  signaled) and which output streams had ended; the drain wait running out and whether it was re-armed; the run reported.
  `ContainerWorkload.ended` logs one line (failure, stop asked, killed). No behaviour change.
- Help `.containers`: one advanced sentence on the activity.
- `Tests/VMRunnerTests/WorkloadSeamTests.swift` ("a workload without a screen holds nothing") is NOT changed: it is about
  the controller's latency activity with a fake workload, a different activity from the container's own.
- The debugger's scratch timing tests (`V-artifacts/ScratchStopTimingTests.swift`) are not part of this card: they take real
  seconds.

New tests (`Tests/VMRunnerTests/ContainerActivityTests.swift`, a spy host, fake runner scripts, a registry per test):
`theActivityIsUserInitiatedAndDoesNotKeepTheMacAwakeOrAskForLatency`, `aRunningContainerHoldsOneActivityUntilItsRunnerEnds`,
`aStartThatThrowsHoldsNothing`, `aRunnerThatFailsBeforeItIsReadyEndsTheActivityItBegan`,
`aWorkloadReleasedWhileItsRunnerRunsEndsItsActivity`. Existing tests changed: none.
