# F02 — A lookup that waited past the proxy's timeout is answered SERVFAIL, not run late

Model: haiku · Effort: low · Worktree: yes, `WT = ~/Developer/g-cqd/VMRunner-chains/f-followups` (branch `chain/f-followups`) · Chain: F, card 2 of 12 (after F01; next F03)

Anchors: locate every edit by its text (`grep -nF`), never by a line number. Verified on `main` at `a98fd14`.

Why (read from the code): `SystemNameResolver.lookup` hands each lookup to `ResolverWorkers`, which runs it on at most 32
threads and queues up to 256 more. The DNS proxy answers SERVFAIL to the guest once `UserNetConfig.dnsTimeout` (5 seconds)
has passed (`DNSProxy.expire(now:)`), but a queued lookup still runs whenever a worker takes it, however late: nobody waits
for its result (`DNSProxy.complete` returns nil for a token it no longer holds), and a server that black-holes queries can
keep every worker busy with such lookups (`getaddrinfo` has no timeout of its own). After this card each queued lookup
carries a deadline (the moment it was submitted plus `maximumWait`, the proxy's timeout); a worker that takes it at or past
the deadline runs its `late` job instead, which answers SERVFAIL at once. The clock is injected (`now`), so the test drives
time with TestKit's `TestClock` and never sleeps.

```swift
/// A few threads of their own for lookups that block (`getaddrinfo`, `DNSServiceProcessResult`), so no cooperative-pool thread
/// ever waits on the system resolver. A burst starts at most `maximumWorkers` threads; each runs lookups one after another until
/// none waits, then ends, so a quiet stack holds no thread. A lookup that waited `maximumWait` or longer for a worker runs its
/// `late` job instead: whoever asked has given up on it by then.
final class ResolverWorkers: Sendable {
    typealias Job = @Sendable () -> Void

    /// A lookup, what runs instead when no worker took it before `deadline`, and that deadline.
    private struct Entry {
        let run: Job
        let late: Job
        let deadline: ContinuousClock.Instant
    }

    private let queue: Mutex<ResolverQueue<Entry>>
    private let maximumWait: Duration
    private let now: @Sendable () -> ContinuousClock.Instant

    /// `now` reads the clock; tests pass one they move by hand.
    init(
        maximumWorkers: Int, maximumQueued: Int, maximumWait: Duration,
        now: @escaping @Sendable () -> ContinuousClock.Instant = { .now }
    ) {
        queue = Mutex(ResolverQueue(maximumWorkers: maximumWorkers, maximumQueued: maximumQueued))
        self.maximumWait = maximumWait
        self.now = now
    }

    /// Runs `job` on a worker thread soon, or `late` instead when the job waited `maximumWait` or longer for a worker. Exactly
    /// one of the two runs. Returns false, and runs neither, when every worker is busy and the queue is full.
    func submit(_ job: @escaping Job, late: @escaping Job) -> Bool {
        let entry = Entry(run: job, late: late, deadline: now().advanced(by: maximumWait))
        switch queue.withLock({ $0.admit(entry) }) {
        case .startWorker:
            Thread.detachNewThread { [self] in
                entry.run()
                drain()
            }
            return true
        case .queued:
            return true
        case .refused:
            return false
        }
    }

    private func drain() {
        while let entry = queue.withLock({ $0.next() }) {
            if now() < entry.deadline { entry.run() } else { entry.late() }
        }
    }
}
```

        let start = ContinuousClock.now

        let done = AsyncEventProbe<Int>()

    @Test func aLookupThatWaitedPastItsDeadlineIsAnsweredLateWithoutRunning() async throws {
        let start = ContinuousClock.now
        let clock = TestClock()
        let workers = ResolverWorkers(
            maximumWorkers: 1, maximumQueued: 4, maximumWait: .seconds(5), now: { start.advanced(by: clock.now.offset) })
        let release = DispatchSemaphore(value: 0)

        release.signal()
        let events = try await done.wait(forAtLeast: 3)
        #expect(events == ["busy ran", "waited late", "fresh ran"])
    }
