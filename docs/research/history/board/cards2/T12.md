## Why

The next step of roadmap 0014 (ADR-NNNN item 7) is a keyboard and a pointer for a Linux machine whose display is the host-implemented GPU. Like the GPU, the input device is a virtio device the host implements through the framework's custom virtio devices, and like the GPU its decisions are a pure library the app's adapter feeds. This card is that library and its tests; the adapter and the machine's configuration are a later card.

**The limit that shapes the library (macOS 27.0 SDK, read from the headers).** The host never learns that the guest wrote `select` and `subsel` of the configuration space: the framework has no callback for the guest's write, and the only configuration API is the host's `update(_:)`, which replaces the whole space with the same size. So the guest reads the same `size` (byte 2) and the same 128-byte union (bytes 8 to 135) for every question. The Linux driver (`drivers/virtio/virtio_input.c`, `virtinput_probe`, read from the tree on 2026-10-25) asks, in this order: the name (`min(size, 64)` bytes of the union), the serial number (the same bytes), the ids (four 16-bit words from the start of the union when `size` is at least 8, else bus 6), the property bits (the first 32 bits), `EV_REP` (advertised when `size` is not 0), then for `EV_KEY`, `EV_REL`, `EV_ABS`, `EV_MSC`, `EV_SW`, `EV_LED` and `EV_SND` the bitmap of the type (advertised when `size` is not 0, clipped to `size × 8` bits and to the type's count: 768, 16, 64, 8, 17, 16 and 4), then, for each absolute axis found, its range as five 32-bit words from the start of the union (minimum, maximum, fuzz, flat, resolution; no check of `size`), and, when `ABS_MT_SLOT` (bit 47) is among the axes, `input_mt_init_slots(max + 1)`, which the probe returns as an error when the count (an unsigned) is above 1024. The input core then refuses to register an absolute device that has no axis. Everything is one bitmap, read as all of these at once.

So the library offers two **static layouts**, each built so that the driver's probe accepts it, both device ID 18 with two queues (event queue 0, status queue 1) and `VIRTIO_F_VERSION_1`:

- **`VirtioInputStaticConfig.keyboard`**: bit 0 and every key `VirtioKeyMap` maps, in 59 bytes (`KEY_FN` is bit 464, byte 58). The mapped keys cover bits 1 to 63 without a gap, so the 32-bit word of bytes 4 to 7 is all ones, `-1`: that is the maximum of `ABS_MT_SLOT` (bit 47 is `KEY_V`), so `max + 1` is 0 and the driver makes no multitouch slot; with any other value it would fail the probe or fail it later (`0x8000` gives 32 769 slots, refused). Bit 0 is `KEY_RESERVED`, which the guest's input core clears; it is set so that `ABS_X`/`ABS_Y` and `REL_X`/`REL_Y` come in pairs, because the guest's input library rejects a device that has one of a pair. Side effects, all asserted by `StaticConfigTests`: absolute axes 0 to 63, relative axes 0 to 15 (the wheels included), LEDs 0 to 15, switches, misc and sounds from the same bits, property bits 0 to 31 (among them the accelerometer property: the guest's device manager tags the keyboard as an accelerometer too, and its input library, which ignores a pure accelerometer, keeps a device that also has keys and disables the accelerometer's axes), ids `0xFFFF` in the four fields, a name of 16 bytes that are not text, and the `EV_REP` bit, so the guest repeats a held key by itself.
- **`VirtioInputStaticConfig.tablet`**: an absolute pointer. `ABS_X` and `ABS_Y` (bits 0 and 1) and `REL_WHEEL` (bit 8) are in the first word, so **the range starts at 259, not 0** (that word is the minimum of every axis); the maximum is the next word, `0x4000` (bit 14 of it is bit 46 of every bitmap), so the range is 259 to 16 384, about 3 steps per pixel on a 5K display; the buttons `BTN_LEFT`, `BTN_RIGHT` and `BTN_MIDDLE` are bits 272 to 274 (byte 34, so the size is 35). The guest's position is a point of that range from the top left corner of its display to the bottom right one. Side effects, asserted: relative axes `REL_X`, `REL_Y` (never moved) and `REL_WHEEL`; **no horizontal wheel**, because `REL_HWHEEL` is bit 6 and bit 6 of the property bits is `INPUT_PROP_ACCELEROMETER`, which would make the guest's device manager call the pointer an accelerometer; the properties `POINTER` and `DIRECT` (a pointer with a mouse button is still a mouse for the device manager); the keys `KEY_ESC`, `KEY_7` and `KEY_C` (bits 1, 8 and 46), the absolute axes 0, 1, 8 and 46 with the same range, ids bus `0x0103`, vendor 0, product `0x4000`, and a two-byte name.

Both layouts pass the probe. The userland behaviour (the accelerometer property, the pairs of axes, a mouse with absolute axes) was read from the sources of the guest's device manager and input library; **none of it has been run against a guest**, which is what would confirm it.

**What the library holds** (`Sources/VirtioInput`, five files, `package` access, no import):
- `InputWire`: the device's constants (ID 18, PCI class 0x09 subclass 0x80, two queues, `VIRTIO_F_VERSION_1`, 8-byte events, 136-byte space), `InputEvent` (type, code, signed value; 8 little-endian bytes; decoding refuses any other length), the codes the library names and `PointerButton`.
- `VirtioKeyMap`: `linuxKey(forMacKeyCode:)` for the 115 keys of a Mac keyboard (ANSI, the ISO section key as `KEY_102ND`, modifiers with left and right, `KEY_FN` for the Function key, F1 to F20, the keypad, the navigation keys, the volume keys, Help as `KEY_INSERT`, the context menu as `KEY_COMPOSE`); the JIS keys and any other code are `nil`. The table was checked against `kVK_*` in the SDK's `Events.h`: all 115 codes exist there, they are distinct, and no two share a Linux key. No AppKit import: the app passes `NSEvent.keyCode`.
- `VirtioInputStaticConfig`: the two layouts and `tabletRange`.
- `InputEvents`: the frames the host sends, each ending in `EV_SYN`/`SYN_REPORT`: key (press, release; `autorepeat` exists but the host sends none because the guest repeats by itself), button, pointer, wheel. **The pointer's origin is the view's top left, y growing downwards, as the guest's**; an AppKit caller (origin at the bottom left) passes `viewHeight - y`. A position is scaled to the range and clamped: NaN, a zero, negative or NaN extent land at the start of the range, infinities on an edge, and nothing can trap.
- `InputEventQueue<Buffer>`: events wait in a list bounded at 256 (the initializer's default); the adapter gives every buffer it takes from the event queue to `hold` instead of giving it back, and the queue writes one event into each buffer, oldest first, and gives the buffer back. Only whole frames (up to a report) are written, and a full queue drops the frame being added whole, with the rest of it up to its report, as the specification advises (a dropped frame can be a release: the guest then keeps the key down until it sees the key again, which `droppedFrameCount` tells the adapter). A buffer smaller than 8 bytes, or one whose write fails, is given back with nothing written and the event waits for the next buffer. At most 1024 buffers are held; one over the limit is given back at once (a driver posts 64).
- `InputStatus.serve`: one buffer of the status queue is decoded and given back exactly once. Exactly 8 bytes are an event (`EV_LED` for a keyboard's lights, which the host ignores today); any other length (0, 7, 9, 4096, a length near `Int.max`) is `malformed` and nothing is read.

**The tests (`Tests/VirtioInputTests`, 46 tests).** `LinuxInputProbe` is a model of the driver's probe, in the test target (not the library: nothing in the app would call it, and `deadwood` would flag it): given the 136 bytes it returns what the driver registers (name, ids, properties, event types, the bitmaps, each axis's range) or the failure (an absolute device without an axis, a slot count above 1024). Its own rules are pinned by hand-made spaces (`LinuxInputProbeTests`) and by 5000 seeded random spaces that never trap it. The layouts, the key table, the encoder (20 000 random sets of four `Double` bit patterns, NaN and infinities among them, scaled into random ranges, always inside the range), the queue (including 100 000 seeded random operations: the bounds hold, every event is delivered, dropped or pending, every buffer is returned at most once, and what the guest saw is a subsequence of the frames that were sent, whole) and the status decoder (random lengths and bytes) are tested like the GPU's decoder. `XorShiftGenerator` is the tests' own generator, written differently from the GPU tests' so that `dolly` finds no exact clone.

**Layering.** `ModuleBoundaryTests` gains `theVirtioInputLibraryDependsOnNothingAndImportsNothing` (no target, no product, no import) and `Sources/VirtioInput` joins the directories that import no user-interface or virtualization framework. `Package.swift` adds `VirtioInput` and `VirtioInputTests`; `.vmr.json` adds the test bundle to the coverage list; README, CONTRIBUTING, roadmap 0014 and ADR-NNNN (a one-line update of item 7) say what exists.

**Judgement calls (recorded; do not change them):**

1. **Both layouts are kept; none had to be dropped.** Each is accepted by the probe model. The cost of each is the list of side effects above, written on the layout's doc comment and asserted in `StaticConfigTests`.
2. **The tablet range is 259 to 16 384, not 0 to 32 767.** The minimum is the 32-bit word of the first four bytes, which carry the bits of `ABS_X`, `ABS_Y` and `REL_WHEEL`, so it cannot be 0; 32 767 would set 15 bits of the shared bitmap (keys, axes and so on) and 16 384 sets one. The guest scales by the range, so the pointer lands where it should; `VirtioInputStaticConfig.tabletRange` is what the encoder takes.
3. **No horizontal scroll.** `REL_HWHEEL` and `INPUT_PROP_ACCELEROMETER` are the same bit; a pointer the guest takes for an accelerometer is worse than one without a horizontal wheel. `InputEvents` has a vertical `scroll(notches:)` only. If the accelerometer turns out harmless in a guest run, the bit can be added with a change of the tablet's tests.
4. **`KEY_FN` is mapped** (`Function` to 464): it fits the 59-byte bitmap and costs only a longer name (which is junk anyway).
5. **`deadwood`:** the library is linked by nothing, so the dead-code gate reported 14 declarations (12 `referenced-only-by-tests`, and the constants `eventQueue` and `statusQueue` as unused). The two unused constants are now read by `theWireConstantsAreThoseOfTheSpecification`; two private constants it flagged were folded into the closures of `keyboard` and `tablet`; each of the 12 declarations left carries the trailing `// @dw:accept:this referenced-only-by-tests -- the app links it later`, the form ADR-NNNN item 2 gives. The card that links the library removes every directive.
6. **The probe model is in the tests**, so the library stays small and the app later may log nothing from it.
7. **The event queue's policies** (a frame is the unit; the newest frame is dropped; complete frames only; a failed write keeps the event; 1024 held buffers) are the library's, tested; the specification asks only that the device drop whole sequences. Returning a buffer without an event is a last resort and is documented as such.
8. **The status queue is strict:** exactly 8 bytes, else nothing is read. A longer buffer is not read in part.
9. **PCI class 0x09 (input device controller), subclass 0x80 (other)** for both layouts: the guest binds by the virtio device ID, the class is only what the PCI tools print.
10. **No outside project is named in the repository text:** the guest's device manager and input library are called so in the code and the docs.

/// the feature bit it needs (virtio specification 1.2, section 5.8).
package enum InputWire {
    /// The virtio device ID of an input device.
    package static let deviceID: UInt16 = 18
    /// PCI class 0x09, input device controller.
    package static let pciClassID: UInt8 = 0x09
    /// PCI subclass 0x80, "other input controller": the guest binds by the virtio device ID, not by this.
    package static let pciSubclassID: UInt8 = 0x80
    /// The event queue (device to driver) and the status queue (driver to device).
    package static let queueCount: UInt16 = 2
    package static let eventQueue: UInt16 = 0  // @dw:accept:this referenced-only-by-tests -- the app links it later
    package static let statusQueue: UInt16 = 1  // @dw:accept:this referenced-only-by-tests -- the app links it later
    /// `VIRTIO_F_VERSION_1` is feature bit 32: bit 0 of the upper 32-bit half of the feature set. The Linux driver refuses a device
    /// without it.
    package static let versionOneFeatureSubset1: UInt32 = 1
    /// One event on either queue: type, code and value.
    package static let eventSize = 8
    /// `struct virtio_input_config`: select, subsel, size and five reserved bytes, then a union of 128 bytes.
    package static let configSize = 136  // @dw:accept:this referenced-only-by-tests -- the app links it later
}

/// The event types the library produces. The codes are those of the Linux input subsystem, which the guest's driver passes on
/// unchanged.
package enum InputEventType {
    package static let syn: UInt16 = 0x00
    package static let key: UInt16 = 0x01
    package static let rel: UInt16 = 0x02
    package static let abs: UInt16 = 0x03
}

/// The event codes the library names, from `input-event-codes.h`.
package enum InputCode {
    /// `ABS_X` and `ABS_Y`: the pointer's position, from the top left of the guest's display.
    package static let absX: UInt16 = 0x00
    package static let absY: UInt16 = 0x01
    /// `REL_WHEEL`: the vertical scroll wheel, in notches, positive away from the user.
    package static let relWheel: UInt16 = 0x08
}

/// The buttons of the pointer, by their `BTN_*` code.
package enum PointerButton: UInt16, CaseIterable, Sendable {  // @dw:accept:this referenced-only-by-tests -- the app links it later
    case left = 0x110
    case right = 0x111
    case middle = 0x112
}

/// One input event as the queues carry it: a little-endian 16-bit type, a 16-bit code and a signed 32-bit value (`struct
/// virtio_input_event`).
package struct InputEvent: Equatable, Sendable {
    /// `EV_SYN` with this code closes a frame: the guest's input core delivers the events before it as one.
    package static let report = Self(type: InputEventType.syn, code: 0, value: 0)

    package var type: UInt16
    package var code: UInt16
    package var value: Int32

    package init(type: UInt16, code: UInt16, value: Int32) {
        self.type = type
        self.code = code
        self.value = value
    }

    /// The event in the 8 bytes a buffer of the event queue takes.
    package var bytes: [UInt8] {
        let word = UInt32(bitPattern: value)
        return [
            UInt8(truncatingIfNeeded: type), UInt8(truncatingIfNeeded: type >> 8),
            UInt8(truncatingIfNeeded: code), UInt8(truncatingIfNeeded: code >> 8),
            UInt8(truncatingIfNeeded: word), UInt8(truncatingIfNeeded: word >> 8),
            UInt8(truncatingIfNeeded: word >> 16), UInt8(truncatingIfNeeded: word >> 24),
        ]
    }

    /// Decodes exactly 8 bytes; any other length is not an event.
    package init?(bytes: [UInt8]) {
        guard bytes.count == InputWire.eventSize else { return nil }
        type = UInt16(bytes[0]) | UInt16(bytes[1]) << 8
        code = UInt16(bytes[2]) | UInt16(bytes[3]) << 8
        var word: UInt32 = 0
        for index in (4..<8).reversed() { word = word << 8 | UInt32(bytes[index]) }
        value = Int32(bitPattern: word)
    }

    /// Whether this event closes a frame.
    var endsFrame: Bool { type == InputEventType.syn && code == 0 }
}

/// The device-specific configuration space of a virtio input device (`struct virtio_input_config`, 136 bytes), as one of two fixed
/// layouts, `keyboard` and `tablet`.
///
/// Why fixed: the Virtualization framework tells the host nothing when the guest writes `select` and `subsel`; the host can only
/// replace the whole space with `update(_:)`. So the guest reads the same `size` and the same 128-byte union whatever it selects.
/// The Linux driver (`drivers/virtio/virtio_input.c`) reads that one union as the device's name, its serial number, its ids,
/// its property bits, the bitmap of every event type it asks about (key, relative, absolute, misc, switch, LED, sound) and the
/// range of every absolute axis it finds. Each layout is one bitmap chosen so that those readings add up to a device the driver
/// accepts and userland treats as intended. The tests replay the driver's probe on the bytes (`LinuxInputProbe`). What follows
/// was derived from the driver's sources and from the sources of the guest's device manager and input library, and has not been
/// run against a guest.
///

    ///
    /// The mapped keys cover bits 1 to 63 without a gap, and bit 0 (`KEY_RESERVED`, which the guest's input core clears) is set
    /// too, so `ABS_X` and `ABS_Y`, `REL_X` and `REL_Y` and the two multitouch positions come in pairs, which the guest's input

    ///   driver sets up no multitouch slots and the probe succeeds;

    /// - property bits 0 to 31, among them `INPUT_PROP_ACCELEROMETER`: the device manager tags the device as an
    ///   accelerometer as well as a keyboard, and the input library then ignores its axes and keeps the keyboard;
    /// - the ids `0xFFFF` everywhere, and a name of 16 bytes that are not text.

    /// 32-bit word, 259; the maximum is the next word, 0x4000 (about 3 steps per pixel across a 5K display); and the buttons are
    /// bits 272 to 274, in byte 34.
    /// The same bytes are the other bitmaps, so the guest also believes:
    /// - relative axes `REL_X`, `REL_Y` and `REL_WHEEL` (the first two never move), and no horizontal wheel: its bit, 6, is
    ///   `INPUT_PROP_ACCELEROMETER` in the property bits, which would make the device manager call the pointer an accelerometer;
    /// - the properties `INPUT_PROP_POINTER` and `INPUT_PROP_DIRECT` (the device manager still calls it a mouse: it has a mouse button);
    /// - the keys `KEY_ESC`, `KEY_7` and `KEY_C`, from bits 1, 8 and 46 (46 is the maximum's top bit), and absolute axes 0, 1, 8
    ///   and 46 with the same range and no fuzz, flat or resolution;
    /// - the ids bus `0x0103`, vendor 0, product `0x4000`, version 0, and a name of two bytes that are not text.
    package static let tablet: Self = {  // @dw:accept:this referenced-only-by-tests -- the app links it later

        let buttons = PointerButton.allCases.map { Int($0.rawValue) }
        // The maximum is the second 32-bit word of the union, which is bits 32 to 63 of every bitmap.
        let maximum: UInt32 = 0x4000
        return Self(bits: axes + (0..<32).filter { maximum >> $0 & 1 == 1 }.map { 32 + $0 } + buttons)
    }()

    /// The range of `ABS_X` and `ABS_Y` of `tablet`, read back from its bytes: the guest's pointer position is a point of this
    /// range, from the top left corner of its display to the bottom right one.
    package static let tabletRange: ClosedRange<Int32> = {  // @dw:accept:this referenced-only-by-tests -- the app links it later
        let low = Int32(bitPattern: tablet.word(at: 0))
        let high = Int32(bitPattern: tablet.word(at: 4))
        return low...max(low, high)
    }()

    /// A space whose union is the bitmap with these bits set, and whose size is the bitmap's length in bytes (at most 128: higher
    /// bits are left out).
    private init(bits: [Int]) {
        let size = min((bits.max() ?? 0) / 8 + 1, 128)
        var union = [UInt8](repeating: 0, count: 128)
        for bit in bits where bit / 8 < size { union[bit / 8] |= 1 << UInt8(bit % 8) }
        bytes = [0, 0, UInt8(size), 0, 0, 0, 0, 0] + union
    }

    /// The little-endian 32-bit word at `offset` of the union.
    private func word(at offset: Int) -> UInt32 {
        let start = 8 + offset
        return bytes[start..<start + 4].reversed().reduce(0) { $0 << 8 | UInt32($1) }
    }
}

            .report,
        ]
    }

    /// The vertical wheel turned by `notches` (positive scrolls up, away from the user); nothing for 0.
    package static func scroll(notches: Int32) -> [InputEvent] {
        notches == 0 ? [] : [InputEvent(type: InputEventType.rel, code: InputCode.relWheel, value: notches), .report]
    }

    private static func scaled(_ value: Double, extent: Double, to range: ClosedRange<Int32>) -> Int32 {
        let ratio = extent > 0 ? value / extent : 0
        let fraction = ratio.isNaN ? 0 : min(max(ratio, 0), 1)
        let low = Double(range.lowerBound)

    }

/// A buffer of the event queue as the device sees it: room the guest left for one event, and the one way back to the guest.
/// The driver posts 8-byte buffers and, when it gets one back, reads an event out of it whatever the used length says, so a
/// buffer returned unwritten shows the guest the event it held last. The queue returns a buffer unwritten only to refuse it.
package protocol GuestEventBuffer {  // @dw:accept:this referenced-only-by-tests -- the app links it later
    /// The bytes the guest left room for.
    var writeCapacity: Int { get }
    /// Writes the bytes into the buffer; called only when they fit `writeCapacity`.
    func put(_ bytes: [UInt8]) throws
    /// Gives the buffer back to the guest, which is told that it is used. Called exactly once per buffer, after any write.
    func giveBack()
}

/// The events waiting for the guest and the buffers the guest has posted, paired one to one: the adapter hands every buffer it
/// takes from the event queue to `hold` instead of giving it back, and the queue gives it back with one event in it.
///
/// Events wait in a bounded list. Only whole frames (events up to an `EV_SYN` / `SYN_REPORT`) are handed to the guest, and when
/// the list is full the frame being added is dropped whole, as the specification advises, so the guest never sees half of one.
/// A dropped frame can be a key's release; the guest then keeps the key down until it sees the key again.
package struct InputEventQueue<Buffer: GuestEventBuffer> {  // @dw:accept:this referenced-only-by-tests -- the app links it later
    private let capacity: Int
    private let maxHeldBuffers: Int
    /// Events not yet written to a buffer, oldest first; the first `completeCount` of them end in a report.
    private var pending: [InputEvent] = []
    private var completeCount = 0
    /// The frame being added was dropped and the rest of it, up to its report, is dropped too.
    private var skippingFrame = false
    private var held: [Buffer] = []

    package private(set) var droppedEventCount = 0
    package private(set) var droppedFrameCount = 0
    /// Buffers returned to the guest with no event: too small for one, one a write failed on, or one over the held limit.
    package private(set) var unusedBufferCount = 0

    /// A queue of at most `capacity` events (one at least) that holds at most `maxHeldBuffers` buffers. The driver posts 64.
    package init(capacity: Int = 256, maxHeldBuffers: Int = 1024) {
        self.capacity = max(capacity, 1)
        self.maxHeldBuffers = max(maxHeldBuffers, 1)
    }

    package var pendingEventCount: Int { pending.count }
    package var heldBufferCount: Int { held.count }

    /// Adds the events, oldest first, and writes whatever the held buffers take.
    package mutating func enqueue(_ events: [InputEvent]) {
        for event in events { add(event) }
        drain()
    }

    /// Takes a buffer the guest posted, and writes to it, and to the ones before it, whatever events wait.
    package mutating func hold(_ buffer: Buffer) {
        if held.count < maxHeldBuffers {
            held.append(buffer)
        } else {
            unusedBufferCount += 1
            buffer.giveBack()
        }
        drain()
    }

    private mutating func add(_ event: InputEvent) {
        if skippingFrame {
            droppedEventCount += 1
            skippingFrame = !event.endsFrame
        } else if pending.count == capacity {
            // Full: the frame being added goes whole, the events of it that wait and the rest of it.
            let partial = pending.count - completeCount
            pending.removeLast(partial)
            droppedEventCount += partial + 1
            droppedFrameCount += 1
            skippingFrame = !event.endsFrame
        } else {
            pending.append(event)
            if event.endsFrame { completeCount = pending.count }
        }
    }

    /// Pairs the oldest complete events with the oldest buffers. A buffer that cannot take an event goes back unwritten and the
    /// event waits for the next one; every buffer is looked at once, so this ends.
    private mutating func drain() {
        var buffersUsed = 0
        var eventsSent = 0
        while eventsSent < completeCount, buffersUsed < held.count {
            let buffer = held[buffersUsed]
            buffersUsed += 1
            if buffer.writeCapacity >= InputWire.eventSize, (try? buffer.put(pending[eventsSent].bytes)) != nil {
                eventsSent += 1
            } else {
                unusedBufferCount += 1
            }
            buffer.giveBack()
        }
        held.removeFirst(buffersUsed)
        pending.removeFirst(eventsSent)
        completeCount -= eventsSent
    }
}

/// A buffer of the status queue: what the driver wrote for the device, such as an `EV_LED` event for a keyboard's lights.
package protocol GuestStatusBuffer {
    /// The bytes the guest wrote.
    var byteCount: Int { get }
    /// Copies the first `count` bytes; called at most once.
    func take(count: Int) throws -> [UInt8]
    /// Gives the buffer back to the guest. Called exactly once.
    func giveBack()
}

/// What one status buffer held.
package enum StatusOutcome: Equatable, Sendable {
    /// A well-formed event. The host ignores it today; the lights of a keyboard would follow it.
    case event(InputEvent)
    /// Not one event: any length but 8. Nothing was read.
    case malformed(length: Int)
    /// The 8 bytes could not be read.
    case unreadable
}

/// Serving of the status queue: the driver's messages to the device are decoded and, for now, only counted by the adapter.
package enum InputStatus {  // @dw:accept:this referenced-only-by-tests -- the app links it later
    /// Decodes one status buffer and gives it back exactly once. It reads at most 8 bytes, whatever length the guest claims.
    package static func serve(_ buffer: some GuestStatusBuffer) -> StatusOutcome {
        defer { buffer.giveBack() }
        let length = buffer.byteCount
        guard length == InputWire.eventSize else { return .malformed(length: length) }
        guard let bytes = try? buffer.take(count: length) else { return .unreadable }
        guard let event = InputEvent(bytes: bytes) else { return .malformed(length: bytes.count) }
        return .event(event)
    }
}

/// The Linux virtio input driver's probe (`drivers/virtio/virtio_input.c`, `virtinput_probe`), replayed on the bytes of a
/// configuration space: what the driver would register with the input core, or why it would fail. The host cannot see the
/// guest write `select` and `subsel`, so every read of this model sees the same `size` and the same union, whatever the driver
/// selected; that is the whole point of the model. Reads past the 136 bytes (a `size` above 128) return zeros.
struct LinuxInputProbe {
    enum Failure: Error, Equatable {
        /// `EV_ABS` is advertised but no axis bit is set, so the input core has no `absinfo` and refuses to register.
        case absoluteWithoutAxes
        /// `ABS_MT_SLOT` is advertised with a maximum that makes `input_mt_init_slots` refuse the slot count (above 1024).
        case multitouchSlots(UInt32)
    }

    struct AxisRange: Equatable {
        var minimum: Int32
        var maximum: Int32
        var fuzz: Int32
        var flat: Int32
        var resolution: Int32
    }

    struct Ids: Equatable {
        var bustype: UInt16
        var vendor: UInt16
        var product: UInt16
        var version: UInt16
    }

    // The sizes of the bitmaps in the Linux input subsystem: KEY_CNT, REL_CNT, ABS_CNT, MSC_CNT, SW_CNT, LED_CNT, SND_CNT and
    // INPUT_PROP_CNT.
    static let keyCount = 0x300
    static let relCount = 0x10
    static let absCount = 0x40
    static let mscCount = 0x08
    static let switchCount = 0x11
    static let ledCount = 0x10
    static let soundCount = 0x04
    static let propertyCount = 0x20

    static let evKey = 0x01
    static let evRel = 0x02
    static let evAbs = 0x03
    static let evMsc = 0x04
    static let evSwitch = 0x05
    static let evLed = 0x11
    static let evSound = 0x12
    static let evRepeat = 0x14
    static let absMultitouchSlot = 0x2F

    /// The bytes the driver copies as the name (`min(size, 64)` of them), and as the serial number.
    private(set) var nameBytes: [UInt8] = []
    private(set) var serialBytes: [UInt8] = []
    private(set) var ids = Ids(bustype: 0, vendor: 0, product: 0, version: 0)
    private(set) var properties: Set<Int> = []
    private(set) var eventTypes: Set<Int> = []
    private(set) var keys: Set<Int> = []
    private(set) var relativeAxes: Set<Int> = []
    private(set) var absoluteAxes: Set<Int> = []
    private(set) var miscellaneous: Set<Int> = []
    private(set) var switches: Set<Int> = []
    private(set) var leds: Set<Int> = []
    private(set) var sounds: Set<Int> = []
    private(set) var ranges: [Int: AxisRange] = [:]

    /// The name as a C string: the bytes up to the first zero.
    var name: [UInt8] { Array(nameBytes.prefix { $0 != 0 }) }

    /// The driver's view of the 136 bytes, and the result of probing them.
    static func run(_ config: [UInt8]) -> Result<Self, Failure> {
        var probe = Self()
        let space = Space(bytes: config)
        probe.nameBytes = space.union(count: min(space.size, 64))
        probe.serialBytes = probe.nameBytes
        probe.ids = space.size >= 8 ? space.ids : Ids(bustype: 6, vendor: 0, product: 0, version: 0)
        probe.properties = space.bits(count: propertyCount)
        if space.size != 0 { probe.eventTypes.insert(evRepeat) }
        probe.readBitmaps(space)
        if probe.eventTypes.contains(evAbs) {
            if let failure = probe.readAxes(space) { return .failure(failure) }
        }
        // `input_register_device`: every device reports `EV_SYN`; `KEY_RESERVED` is cleared.
        probe.eventTypes.insert(0)
        probe.keys.remove(0)
        return .success(probe)
    }

    /// One `virtinput_cfg_bits` per event type: nothing when `size` is 0, else the type is advertised, with the bits the union
    /// has among the first `count`.
    private mutating func readBitmaps(_ space: Space) {
        guard space.size != 0 else { return }
        eventTypes.formUnion([Self.evKey, Self.evRel, Self.evAbs, Self.evMsc, Self.evSwitch, Self.evLed, Self.evSound])
        keys = space.bits(count: Self.keyCount)
        relativeAxes = space.bits(count: Self.relCount)
        absoluteAxes = space.bits(count: Self.absCount)
        miscellaneous = space.bits(count: Self.mscCount)
        switches = space.bits(count: Self.switchCount)
        leds = space.bits(count: Self.ledCount)
        sounds = space.bits(count: Self.soundCount)
    }

    /// `virtinput_cfg_abs` for each axis, then the multitouch slots, then the input core's refusal of an absolute device with no
    /// axis at all.
    private mutating func readAxes(_ space: Space) -> Failure? {
        guard !absoluteAxes.isEmpty else { return .absoluteWithoutAxes }
        for axis in absoluteAxes { ranges[axis] = space.range }
        guard absoluteAxes.contains(Self.absMultitouchSlot) else { return nil }
        // `nslots = max + 1` as an `int`, passed as an `unsigned int`: 0 makes no slots, above 1024 is refused. A count from 1 to
        // 1024 cannot occur: bit 47 of the bitmap is bit 15 of the maximum, which is then 0x8000 or more, or negative.
        let slots = UInt32(bitPattern: space.range.maximum &+ 1)
        return slots > 1024 ? .multitouchSlots(slots) : nil
    }

    /// The configuration space as the driver reads it.
    private struct Space {
        let bytes: [UInt8]

        var size: Int { Int(byte(2)) }

        func byte(_ offset: Int) -> UInt8 { offset < bytes.count ? bytes[offset] : 0 }

        func union(count: Int) -> [UInt8] { (0..<count).map { byte(8 + $0) } }

        func word(at offset: Int) -> UInt32 {
            union(count: offset + 4).suffix(4).reversed().reduce(0) { $0 << 8 | UInt32($1) }
        }

        /// The bits of the union below `count` and below `8 × size`.
        func bits(count: Int) -> Set<Int> {
            let limit = min(count, size * 8)
            let union = union(count: (limit + 7) / 8)
            return Set((0..<limit).filter { union[$0 / 8] >> UInt8($0 % 8) & 1 == 1 })
        }

        /// The ids: four 16-bit words from the start of the union, read when `size` is at least 8.
        var ids: Ids {
            let first = word(at: 0)
            let second = word(at: 4)
            return Ids(
                bustype: UInt16(truncatingIfNeeded: first), vendor: UInt16(truncatingIfNeeded: first >> 16),
                product: UInt16(truncatingIfNeeded: second), version: UInt16(truncatingIfNeeded: second >> 16))
        }

        /// The range every absolute axis gets: five 32-bit words from the start of the union, read with no check of `size`.
        var range: AxisRange {
            AxisRange(
                minimum: Int32(bitPattern: word(at: 0)), maximum: Int32(bitPattern: word(at: 4)),
                fuzz: Int32(bitPattern: word(at: 8)), flat: Int32(bitPattern: word(at: 12)),
                resolution: Int32(bitPattern: word(at: 16)))
        }
    }
}
