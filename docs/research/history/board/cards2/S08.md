Decisions:
- **Kind and the virtual-machine sections.** For a container the guest picker, the installation media and the disk and resources sections are not shown (a container has no installer, disk or guest to choose); the name field stays. The kind picker's help button points at the existing `guestSystems` topic: the help catalog has no topic for containers, and adding one is for the documentation card.
- **The container section.** Image (a text field, default the runner's image as its prompt), command (one line), environment (a text editor, one `NAME=value` per line), CPU cores and memory (steppers over `ContainerLimits.cpus` and `ContainerLimits.memoryMiB`, memory in steps of 128 MiB, the smallest memory allowed, so every value shown is valid), and the network (`None` | `Loopback only`) with a sentence under it: loopback gives the container a network device that leads nowhere outside this Mac, because the runner itself reads its frames, so nothing reaches the user's network or the internet.
- **The command line** is split into arguments by a small pure tokenizer, `ContainerInput.arguments(from:)`: spaces and tabs separate arguments, double quotes keep what is between them in one argument (`""` is an empty argument, `a"b c"d` is the one argument `ab cd`), a backslash is an ordinary character (so a double quote cannot be put inside an argument; the field is one line, not a shell), and a quote that is never closed is refused with a message, not guessed at. Empty means the runner's own check, as in the spec.
- **The environment** is read by `ContainerInput.environment(from:)`: one setting per line, in the order written, blank lines skipped, the value is everything after the first `=`, a line without `=` is refused. Whether a name or value is acceptable (letters, digits and underscores; no NUL or newline; no name twice; at most 64) is not decided twice: the config is built and `VMConfig.validate()` says.
- **Making the config.** `NewMachineModel.makeContainerConfig()` trims the image, splits the command, reads the environment, builds `VMConfig.newContainer` with the draft's identity, and calls `validate()`. `containerProblem` is the reason it throws (for a `DecodingError.dataCorrupted`, its description, such as `container.environment must not name A twice`), or `nil`; the sheet shows it in red under the section and `canCreate` is false while there is one. `create(in:)` adds the validated container machine and starts no setup (it is created provisioned); a failure shows the same text as `creationError`. A virtual machine takes the path it took before.
- **Switching kind.** `workloadChanged(to:)`: to a container, a placeholder name (a guest's name) becomes "Container" and a name the user typed stays; back to a virtual machine, the configuration is reset to that guest's defaults, as `guestChanged(to:)` does (identity kept, local installer file forgotten), and the name "Container" becomes the guest's name again. The container draft is kept while the user switches.
- **Sidebar.** A container's row has the `shippingbox` symbol instead of its guest's, and its caption reads `Container · 2 CPU · 512 MiB` (the numbers are the container's own, not the unused virtual-machine ones); the symbol carries an accessibility label of the machine's kind (`Container`, or the guest's name). A virtual machine's row looks as before. The status dot is unchanged.
- **Wording.** The sheet has no title and its buttons (Cancel, Create) are not specific to a virtual machine, so none changes; only the sheet's and the model's comments name the kind. The alert titles and the stop reports that still say "virtual machine" are left for the card that owns the alerts.

```swift
import Foundation

/// Why the text typed for a container's settings cannot be used.
struct ContainerInputError: LocalizedError, Equatable {
    let errorDescription: String?

    init(_ message: String) {
        errorDescription = message
    }
}

/// Turns the text fields of a container's settings into the values a `ContainerSpec` holds.
enum ContainerInput {
    /// Splits one line into arguments, run without a shell. Spaces and tabs separate arguments; a pair of double quotes keeps
    /// what is between them in one argument (`""` is an empty argument, and `a"b c"d` is the single argument `ab cd`).
    /// A backslash is an ordinary character, so a double quote cannot be part of an argument. A quote that is never closed
    /// is refused rather than guessed at.
    static func arguments(from line: String) throws -> [String] {
        var arguments: [String] = []
        var current = ""
        var inArgument = false
        var quoted = false
        for character in line {
            if character == "\"" {
                quoted.toggle()
                inArgument = true
            } else if !quoted && character.isWhitespace {
                if inArgument { arguments.append(current) }
                current = ""
                inArgument = false
            } else {
                current.append(character)
                inArgument = true
            }
        }
        guard !quoted else { throw ContainerInputError("The command has a double quote that is never closed.") }
        if inArgument { arguments.append(current) }
        return arguments
    }

    /// Reads one `NAME=value` setting per line, in the order written. Blank lines are skipped, and the value is everything
    /// after the first `=`. Whether a name or a value is acceptable is for `VMConfig.validate()` to say.
    static func environment(from text: String) throws -> [ContainerEnvironmentEntry] {
        try text.split(whereSeparator: \.isNewline).compactMap { line in
            guard !line.allSatisfy(\.isWhitespace) else { return nil }
            guard let equals = line.firstIndex(of: "=") else {
                throw ContainerInputError("“\(line)” is not a setting. Write each one as NAME=value.")
            }
            return ContainerEnvironmentEntry(name: String(line[..<equals]), value: String(line[line.index(after: equals)...]))
        }
    }
}
```

```swift
    func makeContainerConfig() throws -> VMConfig {
        var spec = container
        spec.image = spec.image.trimmingCharacters(in: .whitespacesAndNewlines)
```
