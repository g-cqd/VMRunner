Model: haiku · Effort: low · Worktree: yes, `WT = ~/Developer/g-cqd/VMRunner-chains/f-followups` (branch `chain/f-followups`) · Chain: F, card 12 of 16 (after F11; next G02)

Why (found by an authorised real-guest run on 2026-10-22): a Linux guest that read `battery` from the host-information share
every 0.1 s for 75 s failed 8 of 695 reads with `No such file or directory`, all within the second of one rewrite.
`HostInfoPublisher.publish()` writes each file with `Data.write(to:options: .atomic)`, which writes a temporary file and
renames it over the old one: the name then points at a new file, and the guest's virtio-fs entry cache still holds the old
one until it revalidates. After this card each file is rewritten **in place**: the existing file is opened, truncated and
written with its whole content in one call, so the name never goes away; a reader sees the old text, the new text or, for a
moment, an empty file. A file that is not there yet is created with `.withoutOverwriting` (which refuses a name that exists,
a link included). The folder stays private and the share read-only (`ConfigurationBuilder` is not touched). The help and
roadmap 0011 tell a guest to read again a file that is empty or missing for a moment.

```swift
    /// Writes `data` over `file` in place: the file keeps its name and inode, and is truncated and then written with its
    /// whole content in one call. A guest reading it through the share sees the old text, the new text or, for a moment, an
    /// empty file, never a missing one: a replace by rename made the name vanish for about a second in a Linux guest, whose
    /// virtio-fs entry cache still held the old file. A file that is not there yet is created, never through a link.
    private static func overwrite(_ file: URL, with data: Data) throws {
        guard FileManager.default.fileExists(atPath: file.path) else {
            try data.write(to: file, options: .withoutOverwriting)
            return
        }
        let handle = try FileHandle(forWritingTo: file)
        defer { try? handle.close() }
        try handle.truncate(atOffset: 0)
        try handle.write(contentsOf: data)
    }
}
```
