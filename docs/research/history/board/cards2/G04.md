Why: `~/Library/Preferences` of the owner holds 199 files `vmrunner-test-<UUID>.plist` and 10 `ManagedPreferencesTests-<UUID>.plist`
of 42 bytes (an empty binary property list). Tests make a `UserDefaults(suiteName:)` named like a domain and empty it with
`removePersistentDomain(forName:)`, which empties the domain but leaves its file. **Deleting the file does not work**: the
orchestrator tried it outside the repository (30 suites per variant: remove the domain, `synchronize()`, delete the file, in
five orders); the files were gone 1 s and 2 s later, and all back 20 s later, rewritten by the system's preferences daemon.
What works: a suite whose name is an **absolute path** keeps its file at that path plus `.plist` (checked: values read back,
`persistentDomain(forName:)` and `objectIsForced(forKey:)` work), so the helper puts the suite in a scratch folder under the
temporary directory and `cleanUp()` removes the folder; nothing ever reaches `~/Library/Preferences`, and a late write from
the daemon does not recreate a deleted folder (checked 20 s later). This replaces INDEX-F's rule "Suite-name `UserDefaults` in
tests are cleaned with `removePersistentDomain`" (see INDEX-F, "Second batch").

The existing stray files are not touched by this card: the integrator deletes them by hand.

1. Create `Tests/VMRunnerTests/ScratchDefaults.swift` with exactly:

```swift
import Foundation
import Testing

/// A preferences suite of its own for one test, which leaves nothing in `~/Library/Preferences`. A suite named like a
/// domain keeps its file there, and emptying it with `removePersistentDomain(forName:)` does not delete the file: the
/// system writes the empty domain back (42 bytes) a few seconds later, even after the file was deleted. A suite named by
/// an absolute path keeps its file at that path instead, so this suite lives in a scratch folder that `cleanUp()` removes.
struct ScratchDefaults {
    /// The suite's name: an absolute path in the scratch folder, without the `.plist` the system adds.
    let name: String
    let defaults: UserDefaults
    private let folder: URL

    init() throws {
        folder = try scratchDirectory()
        name = folder.appending(path: "defaults").path
        guard let defaults = UserDefaults(suiteName: name) else {
            try? FileManager.default.removeItem(at: folder)
            throw CocoaError(.featureUnsupported)
        }
        self.defaults = defaults
    }

    /// The file the system keeps the suite's values in, once something was written.
    var file: URL { URL(filePath: name + ".plist") }

    /// Empties the suite and removes its folder, with the file in it.
    func cleanUp() {
        defaults.removePersistentDomain(forName: name)
        try? FileManager.default.removeItem(at: folder)
    }
}

/// The helper itself: the suite's file is written in its scratch folder, not in the user's preferences, and is gone after
/// the clean-up.
struct ScratchDefaultsTests {
    @Test func theSuiteKeepsItsFileOutOfThePreferencesFolderAndCleanUpRemovesIt() throws {
        let scratch = try ScratchDefaults()
        scratch.defaults.set(true, forKey: "written")
        scratch.defaults.synchronize()
        #expect(FileManager.default.fileExists(atPath: scratch.file.path), "the value is on disk before the clean-up")
        let preferences = URL.libraryDirectory.appending(path: "Preferences", directoryHint: .isDirectory).path
        #expect(!scratch.file.path.hasPrefix(preferences))
        scratch.cleanUp()
        #expect(!FileManager.default.fileExists(atPath: scratch.file.path))
        #expect(!FileManager.default.fileExists(atPath: scratch.file.deletingLastPathComponent().path), "the folder is gone too")
    }
}
```

   (`scratchDirectory()` is the existing helper of `Tests/VMRunnerTests/TestSupport.swift`. `URL.libraryDirectory` is the
   folder `FileManager.default.urls(for: .libraryDirectory, in: .userDomainMask)` returns: both print
   `/Users/<user>/Library` for this non-sandboxed test process.)
