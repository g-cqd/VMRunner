# D01 — F13, part 1: the gate lock is released explicitly, and its test stops retrying

Model: haiku · Effort: low · Worktree: yes, `WT = ~/Developer/g-cqd/VMRunner-chains/d-security` (branch `chain/d-security`) · Chain: D, card 1 of 22 (first; next D02)

Anchors: locate every edit by its text (`grep -n`), never by a line number. Verified on `main` at `73bceb0`.

Why: `GateLock.hold` locks `.build` with `flock(2)` and only closes the descriptor when it is done. A `flock` lock belongs to the
open file, not to one descriptor: while another thread of the test process is inside `posix_spawn` (DevToolsTests spawn many
processes in parallel), the child holds a copy of every descriptor until its exec closes the close-on-exec ones, and the lock
survives the parent's `close` for that moment. That is the likely reason `theLockIsExclusiveAndReleasedWhenTheBodyEnds` failed about once in
40 runs under load and was given a retry (commit `12e110f`); the cause of the flake is not proven, the mechanism is (new test). An explicit `flock(descriptor, LOCK_UN)` releases the lock on the
open file whatever copies remain (flock(2): "If a process holding a lock on a file forks and the child explicitly unlocks the
file, the parent will lose its lock"). The new test proves the mechanism with real system calls, deterministically.

   place (still inside `struct GateLockTests`, before the struct's closing brace):

```swift
    /// Why `hold` unlocks before it closes: `flock` belongs to the open file, so a copy of the descriptor (the one a concurrent
    /// spawn holds until its exec closes it) keeps the lock after a `close`, and only an explicit unlock releases it at once.
    @Test
    func anExplicitUnlockReleasesTheLockWhileACopyOfTheDescriptorIsStillOpen() throws {
        let directory = FileManager.default.temporaryDirectory.appending(
            path: "gate-lock-\(UUID().uuidString)", directoryHint: .isDirectory)
        try FileManager.default.createDirectory(at: directory, withIntermediateDirectories: true)
        defer { try? FileManager.default.removeItem(at: directory) }
        let other = unsafe open(directory.path, O_RDONLY | O_CLOEXEC)
        try #require(other >= 0)
        defer { close(other) }

        let closedOnly = unsafe open(directory.path, O_RDONLY | O_CLOEXEC)
        try #require(closedOnly >= 0 && flock(closedOnly, LOCK_EX | LOCK_NB) == 0)
        let firstCopy = dup(closedOnly)
        close(closedOnly)
        #expect(flock(other, LOCK_EX | LOCK_NB) != 0, "a close leaves the lock with the copy")
        close(firstCopy)
        #expect(flock(other, LOCK_EX | LOCK_NB) == 0, "the last copy's close releases it")
        #expect(flock(other, LOCK_UN) == 0)

        let unlocked = unsafe open(directory.path, O_RDONLY | O_CLOEXEC)
        try #require(unlocked >= 0 && flock(unlocked, LOCK_EX | LOCK_NB) == 0)
        let secondCopy = dup(unlocked)
        defer { close(secondCopy) }
        #expect(flock(unlocked, LOCK_UN) == 0)
        close(unlocked)
        #expect(flock(other, LOCK_EX | LOCK_NB) == 0, "an explicit unlock releases it whatever copies remain")
    }
```
