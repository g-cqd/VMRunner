# G03 — Serial console: say that the catalog's Alpine image needs `console=hvc0`, and how to give it

Model: haiku · Effort: low · Worktree: yes, `WT = ~/Developer/g-cqd/VMRunner-chains/f-followups` (branch `chain/f-followups`) · Chain: F, card 14 of 16 (after G02; next G04)

Anchors: locate every edit by its text (`grep -nF`), never by a line number. Verified on `main` at `a98fd14`; no card F01 to
G02 changes these places (G01 edits the `.hostInformation` entry of the same help file, not `.serialConsole`).

Why (found by an authorised real-guest run on 2026-10-22): the app's own Alpine catalog image
(`alpine-virt-3.24.2-aarch64.iso`, verified) booted to `localhost login:` on the screen, but with `serialConsole` on the
socket stayed silent: the ISO's `boot/grub/grub.cfg` has `console=tty0 console=ttyAMA0` and `set timeout=1`, and the live
system starts no getty on `hvc0`. The app boots an ISO through EFI and does not touch its kernel command line, and editing a
signed vendor image is out of the question, so there is **no code change**: the help topic, ADR-0052 (a dated note; the
status stays `accepted`) and the automation study say that the guest must boot with `console=hvc0` and how. The catalog
entry is not changed either: its `trustNotes` is the one line on who publishes the image and what vouches for it, and the
console is not part of that.

```
**The app's own Alpine image (2026-10-22).** An authorised real-guest run booted the catalog's
`alpine-virt-3.24.2-aarch64.iso` (signature and checksum verified) from the app with `serialConsole` on: the guest
reached `localhost login:` on its screen, but the socket stayed silent (`vmr guest exec` timed out twice, the console
having sent nothing). The ISO's `boot/grub/grub.cfg` has `console=tty0 console=ttyAMA0` and `set timeout=1`, and the
live system starts no getty on `hvc0`. The app boots an ISO through EFI and leaves its kernel command line alone, so
the guest must boot with `console=hvc0`: at the GRUB menu (stop the one-second countdown, `e`, add it to the `linux`
line, Ctrl-X), or, as that run did, from a FAT boot image with the ISO's files and a `grub.cfg` that says
`set timeout=0` and `console=tty0 console=hvc0`, attached as the installer. With it, `/proc/cmdline` ended in
`console=tty0 console=hvc0` and `exec` logged in as root. The netboot image of `vmr guest` gets `console=hvc0` from its
own command line. No image in the catalog is known to start a login on `hvc0` by itself: Alpine's was checked and does
not; the others were not tried. An installed system that runs systemd may start one on `hvc0` in a virtual machine
through its getty generator, which was not tried either.
```
