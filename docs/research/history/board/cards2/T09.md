## Why

T05 gave the app the adapter, T06 to T08 the setting. This card makes the setting do something at the configuration level: a Linux machine set to the custom GPU is configured with that device. The picture is not shown yet (the next card); the guest's resize is not wired yet (the card after).

**The builder.** `ConfigurationBuilder.configureLinux` calls a new `configureLinuxScreen` (an extension in its own file, `ConfigurationBuilder+Screen.swift`; the enum body stays under the lint limit and nothing is disabled). For a machine that does not use the custom GPU it does what the code did (one `VZVirtioGraphicsDeviceConfiguration` with one scanout, the USB keyboard, the USB screen-coordinate pointer). For `config.usesCustomGPU` it adds **no** graphics device, sets `customVirtioDevices` to the one device the machine's custom GPU makes, and keeps the same USB keyboard and pointer. A machine that needs the device and has none to use (the host is older than macOS 27, which is when `VZMachineFactory` makes none) throws `SetupError.unsupportedHost("The custom GPU needs macOS 27 or later on the host.")`: the user sees that sentence, and no machine falls back silently to the framework's device (that would run something other than what was chosen, and the suspend rules of the setting assume the choice is honoured). The serial-console and clipboard code that follows in `configureLinux` is untouched and does not depend on the graphics device (the spice agent port sits on a virtio console device).

**Who makes and holds the device.** `VZMachineFactory.prepare` makes a `CustomGPUSession` **on the main actor**, before the background build, when the machine uses the custom GPU and the host is macOS 27 or later (`CustomGPUSession`: the `CustomGPUDevice` and the `CustomScreen` it draws on; it takes the display size `prepare` was given). It passes the session to `buildInBackground(..., customGPU:)`, then to `VZGuestMachine(customDisplay:)`, which holds it for as long as it lives (and is released with the machine on stop). `Built` is unchanged. The app sees the session only as a `CustomDisplaySource` (non-gated protocol, `Sendable`, main-actor): `screen`, and `makeConfiguration()`, a **nonisolated, macOS 27-gated requirement** (a type that exists from macOS 27 cannot appear in a signature that exists on macOS 26, the package's target, so the protocol is how `Built`'s neighbours, `GuestMachine` and the model can mention the device without naming it). `GuestMachine` gains `customDisplay`, nil by default (test doubles and machines on the framework's device).

**Why the configuration is made in the background.** `ConfigurationBuilder.build` validates the configuration, and validation needs the provider: a scratch program signed with the virtualization entitlement validated a configuration with one custom device and **no provider** and got `VZErrorDomain 2`, "The device was missing a provider." (and the same configuration with a provider is valid). The provider can therefore not be attached after the background build; it is made with the rest of the configuration, from the session made on the main actor. Passing the session in is the design that keeps the object on the main actor (the alternative, creating the device inside the background build, was rejected: the device is main-actor state).

**The screen (no window yet).** `CustomScreen` keeps the newest picture of the scanout and the guest's cursor (`CursorState`: position, hot spot, picture or none, and a generation number that changes when an update sets or clears the picture, so a view that kept a converted copy knows when to make another; a move keeps the picture and hot spot of the update before it; an update that names no usable resource hides the cursor). It also holds the display size the guest was told. The device's sinks write to it.

**The initial display size** is the size `prepare` receives (`StartDisplay` has already applied the 1280-pixel cap for Linux), brought within the library's limits by a new `GPULimits.fittingDisplay(width:height:)`: each side 1 to `maxDisplaySide`, and when a picture of that size does not fit one resource both sides are scaled down together (a 7680 × 4320 request becomes about 5461 × 3072, a 4K or 5K size is kept).

**The notification loop gets a budget** (T05's judgement call 2 left it to this card). `GPUDeviceState.serveTurn(from:on:memory:budget:)` (library, over a new `ElementQueue` protocol the framework's queue conforms to) serves at most `budget` elements and says whether the budget ended the turn. The adapter's budget is 32. When a turn ends on the budget, the device schedules another on the main actor (`Task`, `self` held weakly, at most one pending per queue), because the guest notifies once for a batch and will not again, and the framework gives no way to look at a queue without taking an element: the later turn may find the queue empty. Each element is itself bounded by the library's limits, so the count bounds the time. The library part is tested with a fake queue; the scheduling is the adapter's and needs a framework queue, so no host test covers it.

**Judgement calls (recorded; do not change them):**

1. **`@preconcurrency` on one conformance.** Without it the compiler refuses to use the main-actor `CustomGPUDevice` as the provider's delegate in a nonisolated function ("main actor-isolated conformance ... cannot be used in nonisolated context"). The other conformance (`VZCustomVirtioDeviceDelegate`) is set inside a main-actor callback and stays isolated.
2. **The builder keys on `config.usesCustomGPU`, not on whether a source was passed**, so a start that forgets the source fails loudly instead of showing the wrong device. On a macOS 27 host with no source the message would be misleading, but `prepare` is the only caller and it makes one whenever the host allows.
3. **The builder's graphics choice is tested through `configureLinuxScreen`**, not through `build`: `build` ends with `vz.validate()`, which fails without the virtualization entitlement (as `ConfigurationBuildTests` already allows for), so a test cannot read a built configuration. The tests check that the framework's device gives one graphics device with the scanout size and no custom device, that the custom one gives no graphics device and one custom device with ID 16 (macOS 27 hosts only), and that both keep one keyboard and one pointer. That the whole configuration with a GPU of ID 16, no graphics device and the USB inputs validates was shown with the signed scratch program (it validates; with a graphics device added it validates too), not by a test of the repository.
4. **`CustomGPUSession` and not the device conform to the protocol**, so the device's tests of T05 (`Sinks` initialiser) stay as they are and the screen has one owner.
5. **No `@dw:accept` is needed** (T05 left none): `deadwood` reports nothing.
6. **The library copies the scanout's rows on every flush** (4 MB at 1280 × 800) in `GPUDeviceState`, before any screen decides whether to draw: a scrolling console flushed over 300 times a second in the real run. This card does not change that (a scratch program built with `-O` measured 0.135 ms for the copy at 1280 × 800, so 300 flushes a second are about 4 % of a core; debug builds are slower; not measured in the app); it is recorded in roadmap 0014 as the first item of what remains.

import CoreGraphics
import VirtioGPU

/// The guest's cursor as the window draws it: where it is, the hot spot of its picture, and the picture, if it has one.
struct CursorState: Equatable {
    var x: UInt32
    var y: UInt32
    var hotX: UInt32
    var hotY: UInt32
    /// The cursor's picture in the guest's pixel format, or `nil` while the guest has none (it hid the cursor, or has not set one).
    var picture: ScanoutUpdate?
    /// Changes whenever an update sets or clears `picture`, so a view that kept a converted copy knows when to make another.
    var pictureGeneration: UInt64

    /// The cursor after `update`: a move keeps the picture and hot spot of the update before it.
    static func after(_ update: CursorUpdate, previous: Self?) -> Self {
        var picture = previous?.picture
        var generation = previous?.pictureGeneration ?? 0
        switch update.image {
        case .unchanged: break
        case .hidden:
            picture = nil
            generation += 1
        case .shown(let shown):
            picture = shown
            generation += 1
        }
        return Self(
            x: update.x, y: update.y, hotX: update.hotX, hotY: update.hotY, picture: picture, pictureGeneration: generation)
    }
}

/// What the guest has drawn on a custom GPU's display: the newest picture of the scanout and the state of the cursor. The
/// device gives it each picture and cursor change on the main actor; the window reads it.
@MainActor
final class CustomScreen {
    /// The size, in pixels, of the display the guest was told to use: what its display-information request answers.
    private(set) var displaySize: CGSize
    /// The newest picture of the scanout, or `nil` before the guest's first flush.
    private(set) var frame: ScanoutUpdate?
    /// The cursor, or `nil` before the guest's first cursor request.
    private(set) var cursor: CursorState?

    init(displaySize: CGSize) {
        self.displaySize = displaySize
    }

    func show(_ update: ScanoutUpdate) {
        frame = update
    }

    func show(_ update: CursorUpdate) {
        cursor = CursorState.after(update, previous: cursor)
    }
}

/// One machine's custom GPU: the device the guest talks to and the screen that device draws on. It is made on the main actor
/// when the machine is prepared, and whoever holds it keeps the device alive, because the framework's provider holds the
/// device weakly.
@available(macOS 27.0, *)
@MainActor
final class CustomGPUSession: CustomDisplaySource {
    let screen: CustomScreen
    private let device: CustomGPUDevice

    /// The display starts at `display`, brought within the library's limits (`GPULimits.fittingDisplay`).
    init(display: (width: Int, height: Int)) {
        var limits = GPULimits()
        let size = limits.fittingDisplay(width: UInt32(clamping: display.width), height: UInt32(clamping: display.height))
        (limits.displayWidth, limits.displayHeight) = size
        let screen = CustomScreen(displaySize: CGSize(width: Int(size.width), height: Int(size.height)))
        self.screen = screen
        device = CustomGPUDevice(
            limits: limits, sinks: CustomGPUDevice.Sinks(showFrame: { screen.show($0) }, showCursor: { screen.show($0) }))
    }

    nonisolated func makeConfiguration() -> VZCustomVirtioDeviceConfiguration {
        device.makeConfiguration()
    }
}

import Virtualization

extension ConfigurationBuilder {
    /// A Linux guest's screen and the keyboard and pointer that go with it. The framework's graphics device is the default; a
    /// machine set to the custom GPU gets that device instead, as a custom virtio device, and no framework graphics device at
    /// all. The USB keyboard and pointer stay either way. A host older than macOS 27 cannot build the custom device, and then
    /// `customGPU` is `nil` (`VZMachineFactory.prepare` makes it only where it can).
    static func configureLinuxScreen(
        _ vz: VZVirtualMachineConfiguration, _ config: VMConfig, _ display: (width: Int, height: Int),
        customGPU: (any CustomDisplaySource)?
    ) throws {
        if config.usesCustomGPU {
            guard #available(macOS 27.0, *), let customGPU else {
                throw SetupError.unsupportedHost("The custom GPU needs macOS 27 or later on the host.")
            }
            vz.customVirtioDevices = [customGPU.makeConfiguration()]
        } else {
            let graphics = VZVirtioGraphicsDeviceConfiguration()
            // The framework supports exactly one scanout per graphics device.
            graphics.scanouts = [VZVirtioGraphicsScanoutConfiguration(widthInPixels: display.width, heightInPixels: display.height)]
            vz.graphicsDevices = [graphics]
        }
        vz.keyboards = [VZUSBKeyboardConfiguration()]
        vz.pointingDevices = [VZUSBScreenCoordinatePointingDeviceConfiguration()]
    }
}

import Testing

@testable import VirtioGPU

/// A queue of elements that counts what is taken from it and what is given back.
private final class FakeQueue: ElementQueue {
    final class Element: QueueElement {
        private(set) var givenBack = 0

        var readableByteCount: Int { 24 }
        var writableByteCount: Int { 1 << 20 }

        func read(count: Int) throws -> [UInt8] { request(.getDisplayInfo) }
        func write(_ bytes: [UInt8]) throws {}
        func giveBack() { givenBack += 1 }
    }

    let elements: [Element]
    private(set) var taken = 0

    init(count: Int) {
        elements = (0..<count).map { _ in Element() }
    }

    func nextElement() -> Element? {
        guard taken < elements.count else { return nil }
        defer { taken += 1 }
        return elements[taken]
    }

    var givenBackOnce: Bool {
        elements.prefix(taken).allSatisfy { $0.givenBack == 1 } && elements.dropFirst(taken).allSatisfy { $0.givenBack == 0 }
    }
}

/// A turn takes at most its budget of elements and says whether it must be continued, so a guest that keeps the ring full
/// cannot keep the caller's thread, and one that notifies once for a batch is still served all of it.
struct QueueTurnTests {
    private struct Turn {
        var more = false
        var served = 0
        var handled = 0
    }

    private func turn(_ state: inout GPUDeviceState, _ queue: FakeQueue, budget: Int) -> Turn {
        var result = Turn()
        result.more = state.serveTurn(
            from: queue, on: .control, memory: FakeGuestMemory(), budget: budget, whenHandled: { _ in result.handled += 1 },
            whenServed: { _ in result.served += 1 })
        return result
    }

    @Test
    func aBatchLargerThanTheBudgetIsServedInTurnsAndEveryElementIsGivenBackOnce() {
        var state = GPUDeviceState()
        let queue = FakeQueue(count: 7)
        var turns: [Turn] = []
        var taken: [Int] = []
        for _ in 0..<3 {
            turns.append(turn(&state, queue, budget: 3))
            taken.append(queue.taken)
        }
        #expect(turns.map(\.more) == [true, true, false])
        #expect(taken == [3, 6, 7])
        #expect(turns.map(\.served) == [3, 3, 1] && turns.map(\.handled) == [3, 3, 1])
        #expect(queue.givenBackOnce)
    }

    @Test
    func aQueueThatRunsDryBeforeTheBudgetEndsTheTurnWithNothingLeft() {
        var state = GPUDeviceState()
        let queue = FakeQueue(count: 2)
        let result = turn(&state, queue, budget: 5)
        #expect(!result.more && result.served == 2 && queue.taken == 2 && queue.givenBackOnce)
    }

    @Test
    func aBatchOfExactlyTheBudgetAsksForOneMoreTurnWhichFindsNothing() {
        var state = GPUDeviceState()
        let queue = FakeQueue(count: 4)
        #expect(turn(&state, queue, budget: 4).more, "the queue cannot be looked at without taking an element")
        let next = turn(&state, queue, budget: 4)
        #expect(!next.more && next.served == 0 && queue.taken == 4)
    }

    @Test(arguments: [0, -3])
    func aBudgetBelowOneStillServesOneElement(budget: Int) {
        var state = GPUDeviceState()
        let queue = FakeQueue(count: 3)
        let result = turn(&state, queue, budget: budget)
        #expect(result.more && result.served == 1 && queue.taken == 1)
    }

    @Test

        let queue = FakeQueue(count: 0)
        let result = turn(&state, queue, budget: 8)
        #expect(!result.more && result.served == 0 && queue.taken == 0)
    }
