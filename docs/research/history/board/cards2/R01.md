## Why

A grouped `Form` on macOS never draws a section wider than about 696 pt. When the form is wider than about 742 pt (696 plus a
23 pt margin on each side), it centres that column. Measured on macOS 27:

| pane width | card x-range | card width |
|---|---|---|
| 560 | 23–536 | 512 |
| 700 | 23–676 | 652 |
| 800 | 51–748 | 696 |
| 1100 | 201–898 | 696 |
| 1400 | 351–1048 | 696 |

The editor fills the `NavigationSplitView` detail pane (800 to 1400 pt), so it showed a centred column with the sections floating in
the middle. The New Machine sheet (560) and Settings (520) are under the cap, so they look right. Tried and refused: `.contentMargins(.horizontal, …)`;
`safeAreaPadding`; `frame(maxWidth: .infinity)`; `containerRelativeFrame` row widths (the cards fill, but the row separators stay at
the centred span); a fixed-width column (the scroller ends mid-pane).

The fix: a new `EditorForm` wraps the grouped form and adds a trailing content margin of `width - 742` (never negative), so the form
lays out within its cap, the sections start at the leading edge, and the scroller stays at the pane's edge. The width is measured with
`onGeometryChange` on the form; the margin is a content margin of the scroll content, so it does not change the width it measures.

Evidence (under `~/Developer/g-cqd/vmrunner-board/layout-shots/`): `before-editor-mac-1100.png` against `r1-editor-mac-1100.png`, and `before-mac-security-1100.png` against
`r1-mac-security-1100.png`.

2. Create `Sources/VMRunner/Views/Editor/EditorForm.swift` with exactly:

```swift
import SwiftUI

/// The machine editor's grouped form, with its sections at the pane's leading edge.
///
/// A grouped form never draws a section wider than about 700 points. In a wider space it keeps that width and centres the
/// column, so in the detail pane (800 to 1,400 points) the sections float in the middle, while the New Machine sheet
/// (560 points) and Settings (520) fill their windows from the leading edge. This form adds a trailing content margin for
/// the width beyond that limit: the form lays out within its cap, the sections start at the leading edge, and the scroller
/// stays at the pane's edge.
struct EditorForm<Content: View>: View {
    @ViewBuilder let content: Content

    @State private var width: CGFloat = 0

    /// The widest a grouped form gets before it centres its sections: about 696 points of section and a 23-point margin on
    /// each side. Measured on macOS 27 only; if a later system changes the cap, the sections are centred again inside the
    /// narrower area, not broken.
    static var maxWidth: CGFloat { 742 }

    var body: some View {
        Form { content }
            .formStyle(.grouped)
            .contentMargins(.trailing, max(0, width - Self.maxWidth), for: .scrollContent)
            .onGeometryChange(for: CGFloat.self) {
                $0.size.width
            } action: {
                width = $0
            }
    }
}
```
