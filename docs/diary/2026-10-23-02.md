# Diary — 2026-10-23 (2)

## The local control service, first step

Eleven commits build the control service of roadmap 0005 as ADR-0056 (proposed) decides; each passed `swift run vmr check`.
Scripts and AI agents can list machines, read their state, and start and stop them, over one private local socket, with a
token that grants only what it names, and only on machines that allow it. Nothing here was run in the app, with a real client
or with a real machine: every claim below comes from tests.

### What was built

- A library target, `ControlProtocol`, linked by the app: messages, tokens and their store, the checks, the connection,
  the listener and a small client. It uses the console's socket code, now shared within the package.
- In the app: the Settings switch (off by default), the managed key `AllowControlService`, the per-machine agent access
  switch (off by default, off in the closed profiles, in the exposure summary), the token list in Settings, three help
  topics, and refusals logged without the token. Start, suspend and stop can now be awaited; the menus use the same path.

### Decisions to confirm

The defaults the owner may change are listed with ADR-0056: one request per line; the token in every request; notifications
ignored; a clean stop answers at once; the limits (64 KiB, 4 clients, 64 requests, 10 s, 2 s, 120 s, 32 tokens); the
folder `Control` in the data folder with no fallback when its path is too long; an agent's start never prompts; the
exposure level low; the library's API public, like the console's.
