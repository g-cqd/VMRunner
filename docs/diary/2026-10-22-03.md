# Diary — 2026-10-22 (3)

## The first run on a real guest: display, window, states and input

Roadmap 0037 to 0040. ADR-0034 and ADR-0041 are unchanged. One agent, authorised by the owner for this session under the
conditions in CONTRIBUTING ("Real-guest runs"): a scratch data folder, a guest capped at 2 CPUs and 2048 MiB, only the app's own
window captured and driven, everything removed afterwards.

Set-up: `VMRUNNER_DATA_DIR` was added first (its own commit, with tests and the CONTRIBUTING text). Alpine 3.24.2 `alpine-virt` for
aarch64 was downloaded into an empty folder: 3.24.3 has no `.asc`, so the newest signed release was taken; the SHA-256 matched the
`.sha256` file and the signature verified with `gpg` against the key from the vendor's key page, whose fingerprint is
0482 D840 22F5 2DF1 C4E7 CD43 293A CD09 07D9 495A. The machine was made by the real `NewMachineModel` and `Provisioner` (a test
written for the purpose and not kept) into the scratch folder, then started with `--start`.

### What went wrong

Making the app's window frontmost was needed to type into the guest, and the accessibility calls that move or resize a window
raised the app as well, so it was frontmost for about seven minutes in one stretch (10:08 to 10:15) and again at other times: the
owner's own typing in that time would have gone to the guest. The app keeps its window frame and split positions in the owner's
preferences (the data folder setting does not move them), so the owner's saved window frame for VMRunner was overwritten by this
run's sizes. The first synthetic keys were lost because the machine view has to be clicked before it takes the keyboard and key
presses shorter than about 100 ms were not seen by the guest; those two cost several runs. The first attempt to isolate the
preferences with `CFFIXED_USER_HOME` produced a process with no window and was dropped.

### Left for later

- Whether a Linux desktop follows the window, and so whether "Resize guest display with window" should default to off for new
  Linux machines (one line in `VMConfig.new`; it reverses ADR-0034 item 5 for desktops).
- Why Alpine's kernel gets no event from the framework's power request; a guest that handles it (Ubuntu).
- A macOS guest, full screen in and out, an external display, the firmware text, `GRUB_GFXMODE` on a guest.
- The unattributed main-thread stalls of 62–98 ms while the Filtered stack runs (Time Profiler); building the configuration off
  the main actor.
- The machine view taking the keyboard when a machine starts; `open -n -a` sometimes giving a process without a window.
- Isolating the preferences domain for a scratch run (the window frame lives in the owner's).

### Cleaned

The scratch data folder, the downloaded installer folder with its checksum and signature, the key and the throwaway keyring, the
captures, the helper programs and the logs under `/tmp`, and every process the run started were removed; no process of the run
is left (the framework's helper of each machine ended with its app). The owner's preferences keep the window frame this run wrote.
