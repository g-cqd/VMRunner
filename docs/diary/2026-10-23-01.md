### Decisions

- **Input format.** A strict subset of YAML, read by the library: no dependency, nothing lenient. The study's example
  needs one change: an `env` secret is written as a block map (`TOKEN:` then `secretRef: name` below it), since flow
  collections are refused.
- **Seed image.** An ISO 9660 writer in the library, not `hdiutil makehybrid` (claim 10): the same seed gives the same
  bytes, the tests pin them, and the app starts no subprocess.
- **Fail closed.** What this version cannot honour (installer phases, `ready`, `pre-shutdown`, `user: user`, secrets) is
  refused with its line rather than dropped.

### Not verified

- That cloud-init in a guest finds the `cidata` volume and reads its Joliet names; that `bootcmd`, `runcmd` and the
  per-boot script run as intended; that the `Merge-Type` header merges the two parts as documented. No guest ran.
- That scripts unpacked into `/var/lib/cloud/vmrunner` can be run on every distribution the catalog offers (the folder was
  chosen over `/run`, which some images mount `noexec`; not checked here; no guest has run a script from it), and that
  `base64` exists on each of them.
- That a script and its environment fit in one command argument on every distribution: the compiler refuses a command over
  120 000 bytes, computed from the Linux per-argument limit (128 KiB), not tried.
- That the image reads correctly in a guest: the primary identifiers contain `-` and carry no `;1` version suffix, the
  unused identifier fields of the Joliet descriptor hold UTF-16 spaces, and only the system's `tar` has read the Joliet
  names, so no kernel or cloud-init has.
- That a file swapped between the host check and the read is caught: the check reads once and packs what it hashed, and no
  test races it.
