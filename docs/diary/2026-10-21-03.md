# Diary — 2026-10-21 (3)

## Test support, the network stack, debounced saves, CI

Decisions: ADR-0006, ADR-0007, ADR-0008. Roadmap 0008, 0018, 0021, 0028.

| # | Claim | Probe | Verdict |
|---|---|---|---|
| 1 | A process-wide allocation count is usable in a parallel test run | Ceilings failed in 5 of 5 runs while other suites ran | REFUTED |
| 2 | Counting on the measuring thread fixes it | 15 consecutive full runs of the app's suite | CONFIRMED (0 of 15 failed) |
| 3 | Thread-local storage is safe inside the malloc hook | A hang in 1 of 5 runs after trying it | REFUTED — replaced with `pthread_self()` |
| 4 | The clock rendezvous tests are deterministic | 40 runs of the suite alone | REFUTED — 17 of 40 hung; two tests raced the waiter's registration; after the fix 100 of 100 passed |
| 5 | The network stack allocates nothing per packet | Allocation tests over ARP, DHCP, ICMP, UDP, TCP data | CONFIRMED in a debug build; setup, DNS and event publishing do allocate |
| 6 | The stack works against a real guest | — | NOT RUN |
| 7 | Each keystroke should not rewrite the config | Counted writes | CONFIRMED; debounced to one write per pause, tests on the test clock |

### What went wrong

The first fix attempt for the hanging suite changed language features, which did nothing; bisecting by suite and then by
test found the race. The "stall" reported twice was two concurrent gates and, once, that race.

### Not verified

The user-mode stack against macOS and Linux guests; the CI workflows on GitHub (only linted offline); Developer ID signing
with the virtualization entitlement.
