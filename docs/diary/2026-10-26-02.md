# Diary — 2026-10-26 (2)

## Contain the Windows helper crash

The [enabled/disabled comparison](../research/windows-pmu-crash-2026-10.md) showed an early helper failure with performance-monitoring emulation enabled on macOS build 26A434, while disabling it left the comparison running for 191 seconds without an observed Windows boot. The owner asked to pause TPM work and address the crash.

The capability registry now has an explicit unsafe-build check. The PMU entry records 26A434; both status and application refuse it before selector lookup, object mutation or helper creation. The existing Windows builder presents the reason through its typed capability-unavailable error. No automatic PMU-off fallback is enabled and no additional private API is used. Other host builds retain their prior selector-compatibility policy; that is not a new runtime-safety claim about those builds.

Help explains the observed failure and the limitation. The roadmap cites the evidence. This is containment under the existing fail-closed decision, not a repair to Apple's closed-source helper. Windows boot remains unresolved.
