# Diary — 2026-10-25 (3)

## A Linux machine can use a graphics device and an input device that the app implements, built and tested without a guest

A run of commits turns the host-implemented virtio GPU of the first feasibility study into an option of the app, and adds the
input devices it needs. Each commit was gated before it was made (8/8). No virtual machine was started: everything below comes
from the 27.0 SDK's headers, from validating configurations without starting them, from compiling against the framework, and
from tests on the host that use fakes in place of the framework's queues, elements and machine.

### What was built

- The setting, the policy and the builder: a Linux machine can use the host-implemented GPU, behind macOS 27, with no framework
  graphics device; the machine's factory makes the device and its screen on the main actor and the machine holds them.
- The window: a layer-backed view of the picture and the guest's cursor; a display that follows the window by the same policy
  as the framework's, through the device's configuration space.
- Two input paths behind one protocol, chosen by a hidden developer default, `CustomGPUInput` (`framework`, the default, or
  `virtio`), read when a machine starts: the framework's own view kept behind the picture, or two virtio input devices (a
  keyboard and an absolute pointer) built on a pure library, the machine then having no USB keyboard or pointer.

### Not verified

- Anything a guest does with either device: that the guest's drivers find them, what they classify them as, the first
  pictures and events, the timings, a second resize.
- The static configuration of the input devices is a workaround for the framework's lack of a callback for the guest's write
  of the selector fields: the guest reads one bitmap for every question. Its classification by the guest's device manager and
  input library was read from their sources and never run.
- That the framework's view accepts events passed to it by another view, from a window where it is not the first responder.
- The scroll step of a trackpad, system keyboard shortcuts on the virtio path, and the guest's cursor image with a real alpha.
- The windows were built, never opened.
